# 결과 요약 PDF에 히스토리·분석 넣기 (design-d)

2026-11-17, 사용자 승인(대화에서 3쪽 구성안에 「ㄱㄱ」).

## 왜
「PDF로 내보내기」가 검사항목 표만 담는다. 앱이 보여 주는 나머지 결과(히스토리의 변화, 분석 ①\~④)를
문서로 받을 수 없다. 사용자가 앱 결과 전체를 한 문서로 받게 한다.

## 목표 / 비목표 / 반목표
- 목표: 3쪽 PDF — 1쪽 검사항목(지금 것), 2쪽 히스토리, 3쪽 분석 ①\~④ 요약.
- 비목표: 분석 상세 카드(3뎁스) 전부 싣기, 웹에서 PDF 파일 만들기, 새 의학 판단 추가.
- 반목표: 화면과 PDF가 다른 말을 하는 것. 화면에 없는 해석을 PDF가 지어내는 것.

## 제약
- CO-SHOW 전시 11/18. 네이티브 의존성 추가 없음(APK 다시 prebuild 안 함).
- 갤럭시탭에서 `printToFileAsync`가 동작함(사용자 확인, v3 APK) — 그대로 쓴다.

## 접근
- **A (선택)** 분석 탭 태블릿 1뎁스 요약을 만드는 계산을 공용 함수로 빼서 화면과 PDF가 같이 쓴다.
- B PDF 쪽에 계산을 복사 — 화면을 고치면 PDF가 어긋난다.
- C 화면 캡처 — 새 네이티브 모듈이 필요하고 글자가 살아 있는 PDF가 아니다.

## 정한 것
- 공용 함수 `analysisSummary(...)`(새 파일 `src/analysisSummary.ts`): 그 해 점수·정상/주의/위험 개수·먼저 볼 항목·
  점수에 안 들어가는 신호·② 계산 지표 행·③ 또래 등수 상위 3·④ 우선 행동과 우선 메시지.
  `AnalysisScreen` 태블릿 1뎁스 타일이 이 함수 결과를 쓰도록 바꾼다(화면 모양은 그대로).
- 2쪽 히스토리: 선택 연도까지의 점수 꺾은선(정적 SVG) + `scoreConclusion` 한 줄,
  우려할 변화(`insight.top_concerns`), 크게 바뀐 항목(`highlights`), 또래보다 빨리 변한 항목(`change_pace`),
  다음 검진 권장 연도. 서술 자료는 전체 기록 기준이라 「전체 기록(\~최신 연도) 기준」이라고 밝힌다. 자료가 없으면 그 칸은 뺀다.
- 쪽 나눔은 CSS `page-break-before`. 안내 문구는 마지막 쪽 끝에 붙인다(혼자 빈 쪽으로 넘어가지 않게).
- 키·몸무게(`infoOnly`)는 상태 칸에 「참고」.
- 내 정보 「PDF로 내보내기」·「인쇄 창으로 열기」, 검사항목 「PDF」 세 곳이 같은 PDF를 만든다.
  `App.tsx`가 히스토리·분석 자료를 한 묶음으로 두 화면에 내려준다.
