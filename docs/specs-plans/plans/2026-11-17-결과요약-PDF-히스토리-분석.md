# 결과 요약 PDF에 히스토리·분석 넣기 Implementation Plan


**Goal:** 「PDF로 내보내기」가 검사항목(1쪽)·히스토리(2쪽)·분석 ①~④ 요약(3쪽)을 담은 PDF를 만든다.

**Architecture:** 분석 탭 태블릿 1뎁스 요약 계산을 순수 함수(`analysisSummary.ts`)로 빼서 화면과 PDF가 같이 쓴다. PDF HTML 생성은 react-native를 import하지 않는 순수 모듈(`reportHtml.ts`)로 옮겨 vitest로 시험한다. `App.tsx`가 히스토리·분석 자료 묶음(`PdfExtras`)을 내 정보·검사항목 화면에 내려준다.

**Tech Stack:** Expo SDK 54, React Native 0.81, expo-print, vitest 4 (`npm test` = `vitest run`)

**Spec:** `docs/specs-plans/specs/2026-11-17-결과요약-PDF-히스토리-분석-design.md`

## Global Constraints

- 작업 위치: `worktrees/design-d/frontend-mobile` (브랜치 design-d). 명령은 이 폴더에서.
- 네이티브 의존성 추가 금지. 새 모듈은 react-native·`components/*`를 import하지 않는다(테스트 가능해야 함, 타입 import는 허용).
- 새 의학 판단 금지 — 화면에 이미 있는 값·문구만 옮긴다.
- 화면 모양은 바꾸지 않는다(분석 탭 태블릿 1뎁스, 히스토리 결론 문구 그대로).

## Review Focus

- 분석 자료가 없는 연도(`comboAnalysisByYear[year]` 없음) → ② 칸에 「이 연도에 저장된 추가 분석이 없어요.」, 오류 없이 PDF 생성. (Task 1·3 테스트)
- 히스토리 자료(highlights·insight·changePace)가 null인 실계정 → 2쪽은 점수 그래프·결론만, 빈 제목 없음. (Task 3 테스트)
- 옛 연도(예: 2018) 선택 → 점수 그래프는 2018까지만. (Task 3 테스트)
- 검진이 한 해뿐 → 그래프 대신 점수 한 줄, NaN 좌표 없음. (Task 3 테스트)
- 이름·병원에 `<`·`&` → 이스케이프. (Task 3 테스트)

  ```ts
    topAction: string | null;                         // rankActions 1위 title(ctx)
    priorityMessage: string | null;                   // recommendations.priority_messages[0]
  };
  export function analysisSummary(a: AnalysisInput): AnalysisSummary;
  export function worstInterpretation(...); export function levelSummary(...); // 기존 시그니처 그대로
  ```

### Task 3: PDF HTML 순수 모듈(3쪽)

**Files:**
- Create: `src/reportHtml.ts`, `src/reportHtml.test.ts`
- Modify: `src/reportExport.ts` — `buildHtml`·`esc`·`STATUS_COLOR` 삭제, `buildReportHtml` 사용, `T` import 삭제

**Interfaces:**
- Consumes: Task 1 `analysisSummary`, Task 2 `scoreTrend`
- Produces:
  ```ts
  export type PdfExtras = {
    reports: Report[];
    highlights?: Highlight[] | null; insight?: Insight | null; changePace?: ChangePace[] | null; // RealTimeseries 하위 타입
    recommendationsByYear?: Record<number, RealRecommendations>;
    egfrByYear?: Record<number, RealEgfr>;
    comboAnalysisByYear?: Record<number, RealComboAnalysis>;
    gender: 1 | 2; smoking?: 'never' | 'former' | 'current' | null; alcoholWeeklyG?: number | null;
  };
  export function buildReportHtml(report: Report, metricDefinitions: MetricDefinition[], userName: string, extras?: PdfExtras | null): string;
  ```
  `extras`가 없으면 1쪽만(지금 PDF와 같음).

쪽 구성(본문 문구는 화면 문구 재사용):
- 1쪽: 지금 내용. 상태 칸은 `m.infoOnly ? '참고'(회색 #9CA3AF) : m.status`. 표 대상은 `metricsForReport(report, metricDefinitions)`.
- 2쪽 `<section class="page">` 제목 「히스토리」: `reports.filter(r => r.year <= report.year)` 점수 SVG 꺾은선(폭 520·높이 170, 70·40 경계 옅은 띠, 점마다 연도·점수 글자) + `scoreTrend` 문장. 2해 미만이면 SVG 없이 문장만. 그 아래 소제목 「전체 기록(~{최신연도}년) 기준」과 우려할 변화(`insight.top_concerns`: title·details), 크게 바뀐 항목(`highlights`: metric·message), 또래보다 빨리 변한 항목(`changePace`: metric·pace.text), 「다음 검진 권장: {next_exam_year}년」. 각 묶음은 자료가 없으면 제목째 생략.
- 3쪽 `<section class="page">` 제목 「분석」: ① 내 건강 점수는(점수·scoreLabel·정상/주의/위험·먼저 확인할 항목·outsideScore 목록), ② 검진지에 없는 값(computed 행, 없으면 「이 연도에 저장된 추가 분석이 없어요.」), ③ 같은 또래는 어떤가(peers 「{name} {rank}등」 + 「등수가 높을수록 또래 중 관리가 더 필요한 쪽이에요.」, 없으면 「비교할 수 있는 또래 자료가 없어요.」), ④ 그래서 뭘 하면 되나(`{topAction}부터 시작하면 현재 지표를 가장 크게 움직여요.` + priorityMessage).
- `.page { page-break-before: always; }`. 안내 3줄(지금 문구 그대로)은 마지막 쪽 끝.
