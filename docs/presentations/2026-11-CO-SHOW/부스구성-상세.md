## 1. 업체 제작이 바꾸는 것 — 「판넬 부착」에서 「벽면 그래픽」으로

In-Jeju에서는 900×1200 판넬 한 장을 출력해 거치대에 세웠다. CO-SHOW는 업체가 부스를 짓는다.
레퍼런스로 받은 MedLine+ 부스를 다시 보면, **판넬을 붙인 게 아니라 벽면 자체가 출력물**이다.
좌·정면·우 세 면이 통으로 그래픽이고, 모니터와 집기가 그 위에 얹혀 있다.

우리도 그게 된다. 그래서 사고를 바꿔야 한다.

| | 기존 계획안 | 업체 제작 전제 |
|---|---|---|
| 벽면 | 판넬(포스터)을 각 벽에 부착 | **벽면 3면 그래픽을 통으로 설계** |
| 산출물 | 포스터 출력 파일 | **벽면 원본 + 배치 요청서** |
| 해상도 | A1\~A0 기준 | **실물 크기 기준 고해상도** (§6) |
| 기존 판넬 | 그대로 게시 | **정면 벽면에 재편집해 흡수** |

⚠️ 계획안 §공간 구성의 「각 벽면에 판넬(포스터) 부착」 문구는 **「벽면 그래픽 시공」**으로 고쳐 쓰는 게 맞다.

## 2. ⚠️ 제출 기한이 없다는 말을 여유로 읽으면 안 된다

업체 제작물에는 고유 리드타임이 있다. 통상 이렇다.

```
시안 확정 ──(2~3주 출력·제작)── 입고 ──(설치)── 행사
                                              11/16~17   11/18
```

역산하면 **10월 중순에는 벽면 시안이 확정**돼야 한다. 사업단이 기한을 안 준 것은
"천천히 해도 된다"가 아니라 "업체 일정에 맞춰 알아서 내라"에 가깝다.

**업체 측에 먼저 물어야 할 것: 시안 마감일이 언제인가.** 이게 진짜 기한이다.

## 3. 🔴 와이파이에 데모를 걸지 않는다 — 부스 내 폐쇄망 구성

전시장 공용 와이파이는 관람객 수백 명이 함께 쓴다. 4일 내내 안정적일 거라고 가정할 수 없다.
그런데 우리 데모는 「촬영 → 서버 OCR → 분석 → 결과」라 네트워크가 끊기면 그 자리에서 멈춘다.

**해법: 부스 안에서 네트워크를 닫는다.**

```
   ┌─────────── 부스 내부 (외부 인터넷 불필요) ───────────┐
   │                                                      │
   │   [휴대용 라우터]  ←── 유선/무선 LAN ──→  [서버 PC]   │
   │         ↑                              FastAPI :8000 │
   │         │                              Ollama qwen2.5vl│
   │    Wi-Fi(로컬)                                        │
   │         │                                            │
   │   [태블릿 A]  [태블릿 B]   ← APK 설치본              │
   │                                                      │
   └──────────────────────────────────────────────────────┘
```

- 라우터는 **외부 인터넷 없이도** 태블릿↔서버 PC를 묶어준다
- APK에 라우터 고정 IP(예: `http://192.168.0.10:8000`)를 구워 넣는다
- OCR은 서버 PC의 **로컬 Ollama**로 처리 → 클라우드 의존 0
- 로그인은 **데모 모드**(`EXPO_PUBLIC_ENABLE_DEMO=1`, `root`/`1234`)로 Supabase 의존 제거

이러면 전시장 와이파이가 죽어도 부스는 계속 돈다.
[00 계획서](시연부스-계획서.md) §6의 「결정 1(OCR 구동)」·「결정 2(폴백)」이 이 구성 하나로 함께 풀린다.

### APK 재빌드 조건 (확정)

기존 `헬스에이지_시연용.apk`(2026-08-04)는 백엔드 주소가 `http://10.0.2.2:8000`으로 구워져 있다.
이건 **에뮬레이터 전용 주소**라 실기기에서는 아무 데도 닿지 않는다. 반드시 다시 빌드해야 한다.

| 항목 | 값 |
|---|---|
| `EXPO_PUBLIC_BACKEND_URL` | 라우터 고정 IP (예: `http://192.168.0.10:8000`) |
| `EXPO_PUBLIC_ENABLE_DEMO` | `1` |
| 빌드 | 디버그 아님 — **릴리즈 빌드** (기존 APK엔 `__DEV__` 흔적 있음) |
| 검증 | 태블릿 2대 실기기에서 촬영→분석 완주 확인 |

## 4. 벽면 3면(설명) + 체험존 1개(시연·체험)

**원칙: 벽면은 설명, 체험존은 시연.** 시연 활동을 벽면에 흩지 않고 한 존에 모은다.

그래서 이렇게 갈라진다.

| | 들어가는 것 | 성격 |
|---|---|---|
| **벽면 3면** | 문제 정의 · 시스템 구조 · 데이터 근거 · 차별점 · 기대효과 | 변하지 않는 것 → 출력물 |
| **체험존** | 실제 OCR 진행 화면 · 분석 결과 · 또래 비교 · 복약 A/B | 변하는 것 → 화면 |

「우리가 이런 걸 만들었다」는 벽에, 「진짜 돌아간다」는 화면에.
(판넬 원고 §4의 「판넬 = 왜 믿을 만한가 / 시연 = 진짜 돌아간다」 분업과 같은 논리)

이 구성의 이점 세 가지.
1. **운영 요원이 한 자리에 선다** — 4일 × 하루 20회를 벽면 사이로 옮겨 다니지 않는다
2. **케이블이 짧아진다** — 태블릿 2대와 미러링 모니터가 한 곳에 모인다. 바닥을 가로지르는 HDMI가 없다
3. **벽면이 순수 출력물이 된다** — 모니터를 벽에 걸지 않으므로 전원·신호선이 필요 없고, 업체에 통짜로 넘길 수 있다

부스 3m×3m, 벽면 높이 2.4\~2.5m 가정. 전면은 개방(입구).

```
              ┌──────── 정면(배면) 벽 ────────┐
              │   설명 B — 무엇을 만들었나      │
              │   로고 · 시스템 흐름 · 데이터 근거│
              │        (모니터 없음 · 순수 그래픽)│
   ┌──────────┤                               ├──────────┐
   │ 설명 A   │   ★ 시연·체험존 (유일한 동적 구역)│ 설명 C   │
   │ 왜       │     테이블 · 의자 4            │ 뭐가     │
   │ 필요한가  │     태블릿 2 · 아크릴 5        │ 다른가   │
   │[모니터 ①]│     [모니터 ②] [모니터 ③]      │(그래픽만)│
   └──────────┤                               ├──────────┘
     좌측 벽   └───────── 입구(개방) ──────────┘   우측 벽
```

- **모니터 ①만 부스 바깥을 향한다** — 체험하지 않고 지나가는 관람객용 상시 루프
- **모니터 ②③은 체험존에 붙는다** — 태블릿 미러링·시연·A/B 비교
- 정면·우측 벽면은 모니터 없이 순수 그래픽

동선: **입구 → 설명 A(좌측) → 설명 B(정면) → ★체험존(중앙) → 설명 C(우측) → 출구**

### 설명 A — 좌측 벽면 — 「왜 필요한가」

| 구획 | 내용 |
|---|---|
| 상단 띠 | 헤드라인 — **매년 받는 검진, 결과지는 읽히지 않는다** |
| 중단 | 설문 75명 수치 3개를 크게<br>· 결과지를 거의 안 읽음 **40.6%**<br>· 종이로만 보관 **53.1%**<br>· 관련 앱 사용경험 없음 **65.6%** |

### ★ 체험존 — 중앙 (유일한 동적 구역)

시연과 체험이 모두 여기서 일어난다. 관람객은 앉고, 운영 요원은 이 한 자리에 선다.

| 항목 | 내용 |
|---|---|
| 집기 | 테이블(약 1800×600) + 의자 4석 |
| 태블릿 | 2대 + 거치대 2대 — APK 설치본 |

⚠️ 모니터 ②③은 **체험존에 붙여 설치**한다. 벽걸이로 올리면 태블릿에서 케이블이 부스를 가로지른다.
