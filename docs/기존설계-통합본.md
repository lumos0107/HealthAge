## 1. 한 장 요약

- 한 줄 원칙은 **"토스처럼 말하고, 뱅크샐러드처럼 담는다."** 구조·컴포넌트는 토스, 브랜드색은 초록, 정보 구조는 3층 피라미드다.
- 어려운 정보일수록 아래층에 둔다. **1뎁스는 결론 한 줄, 2뎁스는 요약, 2.5뎁스는 근거 원문.**
- 모든 수치에는 기준(정상범위·지난번 값·또래)을 같이 보여주고, **진단을 단정하지 않는다.**
- 백엔드가 계산한 **자산은 사용자에게 닿아야 한다.** 화면 요소는 정리해도 되지만 무엇을 왜 뺐는지 남긴다.
- 문구는 해요체, 쉬운 말을 먼저 쓰고 용어는 괄호나 작은 회색 라벨로 붙인다.
- 지금까지 분석 탭을 중심으로 대부분의 설계가 이루어졌고, **접근성(글자 크기·대비) 수치는 시니어 기준이 아니라 정보 밀도 기준으로 정해져 있다**(11절).

### 2-2. 층과 깊이 — 이름이 섞이기 쉬운 곳

| 용어 | 뜻 |
|---|---|
| **뎁스** (세로 깊이) | 1뎁스 = 결론 카드, 2뎁스 = 카드를 열었을 때, 2.5뎁스 = 그 안의 접힌 "자세히" |
| **L0\~L3** | 스펙 §2의 옛 이름. L0=홈, L1=1뎁스, L2=2뎁스, L3=2.5뎁스. **코드 어휘(1·2·2.5뎁스)가 정본** |
| **층** (가로 구획) | 분석 탭의 ① 기준을 벗어났나 → ② 검진지에 없는 값을 만들어요 → ③ 같은 또래는 어떤가 → ④ 그래서 뭘 하면 되나 |
| **2뎁스 다섯 칸** | ①결론 → ②정의 → ③나의 위치 → ④의미 → ⑤행동 (순서 고정, 예외 없음) |
| **구획** (`DomainHeader`) | ②층 안에서 장기별(신장/간/대사·지질/심혈관)로 나누는 머리말 |

⚠️ **"층"은 가로, "뎁스"는 세로.** 원문자 ①이 층·칸·홈 TOP 3 번호 세 곳에서 쓰이므로 말할 때 구분한다.

### 2-3. 판단·표시 용어

| 용어 | 뜻 |
|---|---|
| **참고 점수** | 0\~100. 검사 항목별 주의/위험 **개수**로 감점. 계산기·조합·ASCVD 등은 **점수에 안 들어간다**(그래서 "이 점수에 들어가지 않은 신호 N가지"를 따로 보여줌) |
| **배지** | 분석 카드는 양호/주의/**높음**('위험'은 선별용 지표에 쓰지 않음), 검사항목은 정상/주의/위험 |
| **`interpretation` / `plain`** | 같은 판정의 두 벌. `interpretation`=2뎁스 배지·근거, `plain`=**1뎁스 결론** 해요체 문장 |
| **자산** | 백엔드가 계산했거나 데이터로 확보한 것. "타입에만 있고 안 그리면 없는 것" |
| **비교축** | ③ 나의 위치가 비교하는 대상: `standard`(학회 기준) · `peer`(공단 표본 또래) · `time`(과거의 나) 셋뿐 |
| **`PeerRankBlock`** | "같은 나이대 100명 중 N등" 문장+슬라이더+근거 배지(`모집단 분포`/`추정`) |
| **`Expandable`** | 접기. **접힌 것이 곧 2.5뎁스** |
| **`SummaryCard`** | 분석 카드 공통 틀. `axes`(비교축)가 **필수** |
| **`cardContent`** | 카드 문구 모음. **키가 곧 카드 제목** |
| **다음 검진 목표** | 예전 what-if 시뮬레이터를 행동 입력 방식으로 다시 쓴 것(`NextCheckupGoal`) |

## 3. 설계 원칙

스펙 §1-1과 §7, 그리고 각 기록이 반복해서 확인한 것들.

1. **자산은 죽이지 않는다.** 백엔드가 계산한 것은 사용자에게 닿아야 한다. 타입·더미만 있고 그리는 코드가 0건이면 없는 것이다(예: `ldl_target`이 한 번도 안 그려졌던 일).
2. **화면 요소는 정리할 수 있다.** 단, 무엇을 왜 뺐고 어디서 볼 수 있는지 문서나 코드 주석에 남긴다. 조용히 빼지 않는다.
3. **분류·묶음도 근거를 밝힌다.** 학회 기준이면 출처를, 앱이 편의로 묶은 것이면 "임상 분류가 아니라 함께 보기 위한 묶음"이라고 밝힌다.
4. **진단 단정 금지.** "심혈관 위험 12%"를 본 사람이 확정된 예언으로 읽지 않게 ④칸이 오해를 막는다. 선별용 지표에 '위험'이라는 낱말을 쓰지 않는다.
5. **수치엔 항상 해석 한 줄, 기준 없이 숫자만 보여주지 않는다.**
6. **모르는 것을 양호나 주의로 말하지 않는다.** LDL이 TG≥400이면 판정 보류, 데이터가 없으면 "왜 없는지" 밝힌다. 빈칸을 채우려고 문장을 지어내지 않는다.
7. **"되면"이지 "하면"이 아니다.** 목표 수치는 "그 변화가 실제로 일어났을 때"의 값이다. 체중 감량 유지율은 2년에 절반 이상, 5년에 80% 이상 되돌아온다.
8. **효과크기는 더하지 않고, 범위로 쓰고, 출처와 등급을 붙인다.**
9. **이상 소견 화면엔 캐릭터·장식 금지**(심각성이 희석됨). 캐릭터·일러스트 카드는 채택하지 않았다.
10. **같은 사실이 두 곳에 적혀 있으면 언젠가 갈린다.** 판정(status)은 한 곳에서 파생시키고, 프론트가 손으로 적은 기준 숫자는 백엔드 상수와 대조한다.

## 4. 정보 구조 — 3층 피라미드와 뎁스 규격

### 4-1. 세 층이 하는 일

| 층 | 답하는 질문 | 사용자의 다음 행동 | 담는 것 |
|---|---|---|---|
| 1뎁스 | 내가 이걸 봐야 하나? | 연다 / 안 연다 | 결론 한 줄 |
| 2뎁스 | 뭔데 · 나는 어떤데 · 뭘 하면 되는데 | 행동을 정한다 | 요약 |
| 2.5뎁스 | 왜 그렇게 판정했는데? | 믿는다 / 안 믿는다 | 공식·논문·컷오프 근거 |

**판별 테스트**: 문장을 지웠을 때 *열지 말지*가 흔들리면 1뎁스, *믿을지*가 흔들리면 2.5뎁스, 둘 다 아니면 2뎁스.

### 4-2. 다섯 축 (각 층이 어떻게 생겼나)

| 축 | 규칙 |
|---|---|
| 0. 질문 | 위 표대로 층을 가른다 |
| 1. 중요도 × 어려움 | 중요·쉬움 → 1뎁스 그대로 / **중요·어려움 → 1뎁스엔 번역한 결론만, 원문은 2.5뎁스** / 부차·쉬움 → 2뎁스 / 부차·어려움 → 2.5뎁스 |
| 2. 언어 | 1뎁스: 검진지에 **인쇄된** 항목명만(우리가 지은 지표명·약어·공식 금지). 2뎁스: 쉬운 말 먼저, 괄호로 용어. 2.5뎁스: 제한 없음. 선은 "종이에 있나" |
| 3. 분량 | 1뎁스 제목 12자(배지 있으면)/15자, 결론 1문장 40자, 배지 1개. 2뎁스 칸당 1\~3문장, 스크롤 없이 읽히는 분량. 2.5뎁스는 접힌 채 시작, **펼쳐서 6줄 넘으면 3뎁스 검토 신호**(실측 34개 중 5개가 넘음 → "층이 필요한 게 아니라 그 다섯 개가 긴 것") |
| 4. 순서 | 1뎁스는 탭마다 정렬 기준 하나, 화면이 그 기준을 말한다(홈=심각도, 검사항목=심각도, 히스토리=시간→종합, 분석=논리 4단계). 2뎁스는 ①\~⑤ 고정 |

### 4-3. 2뎁스 다섯 칸

| 칸 | 하는 일 | 없어도 되는 때 |
|---|---|---|
| ① 결론 | 1뎁스 판단을 헤드라인으로 | 항상 있음 |
| ② 이 지표는요 | 무엇인지 한 문장(용어 없이) | 제목이 곧 설명 |
| ③ 나의 위치 | "나"를 비교축에 놓아 보여줌 | 비교축이 없으면 |
| ④ 그래서 이게 의미하는 건 | **오해 차단**("유지된다고 가정한 수치예요") | 오해할 여지 없음 |
| ⑤ 그럼 뭘 하면 좋을까 | 행동 | 행동할 게 없음(통계 카드 등) |

- 칸을 지우지 말고 **왜 비었는지 말한다.** 한 칸이 길어지면 칸을 늘리지 말고 소제목으로 나눈다.
- ③의 제목은 비교축에서 파생한다(`positionTitle()`): 축이 하나면 "나의 위치 — 기준과 비교 / 또래와 비교 / 연도별 흐름", 둘 이상이면 "나의 위치". 칸 안 순서는 **기준 → 또래 → 연도**. 축은 **실제로 그려진 것만** 선언한다.
- `peer` 축을 쓰면 근거 한 줄(표본 수·연도)이 **필수**.
- **2뎁스는 요약, 원문은 접는다.** 접기 전에 안에 무엇이 얼마나 있는지 한 줄로 알린다. 접는 버튼은 ②의 "자세히 알아보기"와 같은 모양으로 쓴다.

### 4-4. 1뎁스 카드 규칙

- **판단이 반드시 있어야 한다**(배지 또는 결론 문장 중 하나 이상). 개수·수치 나열로 끝내지 않는다.
  - ✅ "지표 2개 중 1개가 기준 밖이에요" / ❌ "해당 조합 2개"
- **이름은 질문형**: "콩팥이 잘 거르고 있나"처럼 짓고 용어는 제목 *옆* 작은 회색 라벨(`term`)로. 제목에 괄호로 넣으면 축 2에 걸린다.
- **"\~ 검사"로 부르지 않는다.** 검사를 받은 게 아니라 검진 수치로 계산한 값이다.
- **결론은 "답"이지 "값"이 아니다.** 검진지에서 이미 알 수 있는 것을 되풀이하면 카드를 열 이유가 없다(예: "목표 LDL 130 미만, 초과했어요" 대신 "위험 요인 2개라 내 목표는 130 미만 · 지금 178로 48 넘었어요").
- 결론은 해요체로 끝낸다. 명사로 끊으면 표의 한 칸처럼 읽힌다.
- 결론이 옆 카드와 같은 질문을 하면 안 된다. 다만 **읽는 목적이 다르면 같은 데이터를 두 번 써도 된다.**
- 카드 제목의 질문에 답하지 않는 지표는 결론에서 빼고 2뎁스 행으로 옮긴다(자리를 옮길 뿐, 지우지 않는다).

### 4-5. 2뎁스에 무엇을 펴 두나

막는 것은 **양이 아니라 공식**이다. 공식·논문 인용·비고는 2.5뎁스, **제목·판정 배지·값·또래 비교·기준(컷오프)은 2뎁스에 편다.** 컷오프는 값의 눈금이라 없으면 숫자가 좋은지 나쁜지 읽을 수 없다.
여러 지표가 든 카드는 "제목의 질문에 답하는 지표"만 펴고(간이 굳어가고 있나 → BARD만), 지표마다 한 줄 뜻풀이(`calcGloss`)를 값 위에 둔다.

## 5. 화면별 현황과 이미 내려진 결정

### 5-1. 홈
- 참고 점수(큰 숫자 64\~80pt) + "지금 주의할 항목 TOP 3"(번호, 항목명, 쉬운 해석 한 줄, 상태 배지, **수치 없음**) + "전체 보기" + "빠른 이동".
- 모두 정상이면 "모두 정상이에요" 카드.
- "빠른 이동"(검진기관·병원·약국 찾기 버튼)은 판단 요소가 아니라 **도구 카드**라 정렬 규칙(축 4) 대상이 아니다. TOP 3 아래로 내렸다가 되돌린 이력이 있다.
- 홈만 데이터를 따라오지 못하던 버그: 항목별 `status`는 `latest.statusByKey`에서 **파생**시킨다.

### 5-2. 검사항목
- 연도 선택기 + 정상/주의/위험 요약 칩(탭하면 필터) + 검사항목/복용약 세그먼트. 기본 정렬 **주의 순**(위험→주의→정상).
- 행 = 틴트 스쿼클 아이콘 + 항목명 + 값 + 상태 배지 + chevron.
- 항목을 누르면 항목 상세 오버레이.

### 5-3. 항목 상세 (L2 오버레이)
- 풀스크린 슬라이드, 뒤로가기 버튼과 Android 백버튼 처리(iOS 엣지 스와이프 백은 미지원으로 수용).
- 구성: 상태 배지+항목명 → 쉬운 문장 헤드라인("공복혈당이 살짝 높아요") → 전년 대비 한 줄 → 또래 등수 슬라이더(percentile 없으면 정상범위 위치 바만, **추정치를 지어내지 않음**) → "자세히 보기" 펼침(원본 수치·정상범위 표·연도별 추이 차트·용어 설명) → "참고용이며 진단이 아닙니다".
- 상세 안에서 추가 화면 전환 금지, 펼침으로만.
- 연도: 상세 화면 안 연도 칩으로 바꾸고, 연도 상태는 `App`의 `detail.year` **한 곳**이 갖는다. **그 항목을 실제로 잰 해만** 칩에 나온다(안 잰 해를 고르면 상세 화면이 통째로 사라지기 때문).

### 5-4. 히스토리
- 순서: 그래프(점수 추이 → 항목별 추이)를 위로, 글 위주 종합 카드는 뒤로. 스크롤 없이 그래프 3개가 보이게 했다.
- 구획: **「항목별로 보면」(그래프) / 「여러 해를 종합하면」(글)**. 분석 탭 `LayerHeader`와 같은 문법.
- 기준 항목 칩 = 초록 띠·등수·헤드라인의 주인(**기본 켬**), "다른 항목도 함께 보기" 체크박스 = 나머지 선을 배경에 깔지.
- 대표 항목은 **최신 연도로 고정**(연도를 누를 때마다 대표가 갈아타면 연도별 비교가 불가능).
- 방향 표시(▲▼◆): HDL처럼 "높을수록 좋음"인 지표는 올라가는 게 좋은 것임을 범례에 표시.
- 몸무게는 BMI와 상관 1.0이라 제거, 허리둘레는 기준을 넘는 시점이 달라 유지.
- "또래 대비 변화 속도" → **"또래보다 빠르게 변한 항목"**으로 개명. 시제를 뺐다("나빠지고 있어요"는 현재진행형이라 2020년 이후 반등과 충돌).
- 점수 추이 문장은 V자 그래프에 맞춰 "16년간 54점 내려갔지만, 2020년 이후로는 18점 올랐어요."
- 연도 칩은 넣었다가 뺐다(9회차가 두 줄을 차지해 그래프를 밀어냄). 대신 "2024년으로 돌아가기" 버튼.

### 5-5. 분석
**4개 층**
| 층 | 질문 | 대표 카드(1뎁스 이름) |
|---|---|---|
| ① | 기준을 벗어났나 | 참고 점수 카드 → "나는 어떤 상태인가"(집단군 판정, 항목으로 보면/상태로 보면) |
| ② | 검진지에 없는 값을 만들어요 | 콩팥이 잘 거르고 있나 · 간에 지방이 꼈나 · 간이 굳어가고 있나 · 혈당·지질에 이상이 있나 · 내 LDL 목표를 넘었나 · 심혈관 위험이 얼마나 되나 |
| ③ | 같은 또래는 어떤가 | 또래 중 어디쯤인가 · 나 같은 사람이 얼마나 되나 · 또래 자체가 나빠졌나 · 함께 움직이는 게 있나 |
| ④ | 그래서 뭘 하면 되나 | 무엇부터 하면 되나 · 맞춤 권장사항 · 다음 검진 목표 |

- 맨 위에 결론 한 줄(그 해 주의·위험 개수와 "점수 밖 신호"). **새 판단을 만들지 않는다.**
- 연도 칩은 카드 밖으로 빼고, "여기부터 아래 모든 카드는 N년 수치"라고 밝힌다. 그 해 분석이 없으면 카드를 조용히 지우지 않고 **왜 없는지** 말한다.
- 판정 배지는 7장에만(계산 카드). **관찰 카드(집단군 판정·또래 분포·조합·16년 변화)에는 배지를 달지 않는다**(백엔드가 하지 않은 판단을 앱이 만들게 됨).
- LDL은 `achieved`가 null이면 배지 없음(판정 보류).
- 장기 구획 머리말(신장/간/…)은 **15pt·볼드·왼쪽 정렬**이 원안이고, 지우기·11pt 회색·가운데 정렬은 모두 더 나빴다.
- "관리 참고군" 카드 5장은 제거(하던 일이 다른 카드로 갔음). 묶음 근거(`basis`)는 ③층으로 이관했다.
- **또래 비교**: 판정 옆 한 줄(맥락)과 ③의 "또래 중 어디쯤인가"(다른 질문)는 둘 다 둔다. 컷오프가 있는 지표는 학회 기준이 결론을 말하고 또래는 **보조**.
- 계산기 또래의 기준 연도는 **2017 고정이 의도**(2018년 지질검사 4년주기 전환 이후 표본이 1/3로 줄고 이미 관리 중인 쪽으로 쏠림). 전수 측정되는 De Ritis·MAP만 검진 연도로 견준다. 어느 해 기준인지 `peer_year`로 화면이 밝힌다.
- 흡연·음주 유병률은 또래 비교에 **일부러 넣지 않았다**("나만 그런 게 아니네"로 읽혀 행동을 막음).
- 조합그룹: 12개를 네 유형(`same_cause` · `one_worsens` · `different_axis` · `shared_criterion`)으로 묶어 "함께 움직이는 게 있나"로 바꿨다. 조합의 `relation`·`action`은 임상 지식이므로 O/E(실측)와 **같은 무게로 보여주지 않고** 출처를 갈라 말한다. O/E 1.5 미만은 내세우지 않되 근거 목록엔 남긴다.
- 무엇부터 하면 되나: 흩어진 행동을 **모아서 순서만 매긴다**(문구는 기존 그대로). 순서는 "기준까지의 거리가 몇 % 줄어드나"로 매기고 `NextCheckupGoal`과 같은 계산을 쓴다.
- 헤더의 "분석 탭 보는 법"은 설명문만 두면 아무도 안 눌러서 진한 글씨로 버튼처럼 만들었다(네 번 만에 정리).

### 5-6. 업로드
- 흐름: 촬영/선택 → OCR → 검수 → 저장. 하단 고정 CTA, "처리중입니다" 로딩 상태, 예시 결과 미리보기("참고용 더미 데이터" 고지 유지), 복약자료 발급 방법 안내.

## 6. 시각 규격

### 6-1. 토큰 (`UI.tsx`의 `T`)
| 토큰 | 값 |
|---|---|
| 화면 배경 | `#F3F5F7` |
| 카드 | 흰색, **테두리·그림자 없음**, radius 20, 카드 간격 12 |
| 브랜드 그린 | `#00C073` · 눌림 `#00A862` · 틴트 `#E6F9F1` |
| 텍스트 | `#191F28` / `#4E5968` / `#8B95A1` (`T.text3`가 가장 흐림, 이보다 더 흐리게 쓰지 않음) |
| 정상 | `#1F8A5D` (틴트 `#EAF7F1`) |
| 주의 | `#D97706` (틴트 `#FFF3E7`) |
| 위험 | `#F04452` (틴트 `#FEE9EB`) |
| 구분선 | 카드 내부 전용 `#F2F4F6` |
| radius | 카드 20 · 버튼 14 · 입력 12 · 칩 999 |

- **"누를 수 있는 것만 브랜드 그린."** 정상 상태는 `#1F8A5D`로 따로 둔다. 경고 기호에 그린을 쓴 것을 `T.warn`으로 바로잡은 적이 있다.
- 폰트: 전체 Pretendard(가변). 큰 제목/브랜드용으로 Do Hyeon도 사용.
- 구 팔레트 hex는 `src`에서 grep 0건이 완료 기준.

### 6-2. 컴포넌트
- 카드: 연회색 배경 위 흰 카드, 배경 대비로만 구분.
- 리스트 행: 틴트 스쿼클 아이콘 + 제목/캡션 + 우측 값 + chevron.
- 버튼: 브랜드 그린 채움, radius 14, **최소 높이 48**, 라벨은 동사형.
- 입력: 테두리 없는 연회색 채움 `#F2F4F6`, radius 12.
- 상태 배지: 틴트 배경 + 상태색 + **텍스트 병기**(색만으로 구분 금지).
- 차트: 정상범위는 연한 배경 밴드, 축에 단위, 최신(또는 고른 해) 값 강조. `highlightYear`는 **필수 인자**(기본값을 두면 같은 버그가 되살아남).
- 이모지 사용 안 함(`DomainHeader`의 `icon` prop 제거, 백엔드 메시지의 이모지도 제거).

### 6-3. 글자 크기 — 역할별 하한 (2026-08-03 개정)
원래 "본문 16 미만 금지"였는데 실측하면 16 이상은 약 50곳뿐이고 본문 대다수가 13\~15였다. 스펙이 스스로 "L1부터 뱅샐 밀도"라 적어 두 조항이 부딪혔고, **규칙 쪽이 틀렸다**고 결론 내렸다(검진 항목 17개 화면에서 16pt 본문은 담기지 않음).

| 역할 | 하한 |
|---|---|
| 읽는 문장 (①결론·②정의·④의미·⑤행동) | **13** |
| 보조 캡션 (근거·출처·한계·단위·컷오프) | **11** |
| 배지·칩 라벨 | **10** |
| 그 아래 | 금지 |

가르는 기준은 "문장인가". 근거를 작게 쓰는 것은 덜 중요해서가 아니라 문장을 먼저 읽게 하려는 것이다. 색으로 위계를 대신하지 않는다.
타이포: 화면 제목은 작게(24\~26), 핵심 숫자는 크게(점수 64\~80).

## 7. 문구 규칙

- 해요체, 능동형, 긍정형 우선(이상 소견은 명확한 부정형 허용). 어려운 개념은 비유로.
- 카드 이름은 질문형. "\~ 검사"라고 부르지 않는다.
- "상위 91\~100등"처럼 "상위"를 붙이지 않는다(1등=항상 가장 좋음이 아니기 때문).
- 항목명 중복 금지: 바로 위에 항목명이 있으면 헤드라인에서 주어를 뺀다.
- "이 항목은요" → "이 지표는요"(분석에는 검사 항목이 아닌 계산 지표도 있음).
- 이중부정·배제 검사는 직역하지 않는다. BARD가 높은 것은 "섬유화가 있다"가 아니라 "배제할 수 없다"이고, 그 검사가 줄 수 있는 유일한 결론은 "추가 평가 권장"이다.
- 금지/필수 문구: "담배를 **줄이기**"는 제시하지 않는다(한국지질 2022 비권장). 금연 시나리오엔 체중 증가 경고, 감량 시나리오엔 주 1kg 이하 속도 상한을 병기한다. 저염 수치는 고혈압군(140/90 이상)에만 붙인다. 하루 2잔 이하인 사람에게 절주 효과를 말하지 않는다.
- 비흡연자에게 금연 권고를 붙이지 않는다. **모르는 것과 아닌 것을 구분**한다(문진이 비면 키 자체가 없음 → 빼되 이유를 `omitted`에 남겨 화면이 밝힌다).
- 음주 입력 칩에는 잔 크기를 붙인다(`소주 50ml` · `와인 150ml`)— 같은 "3잔"이라도 알코올량이 다르기 때문.

## 8. 데이터 신뢰 원칙

1. **출처가 둘이면 화면이 갈라 말한다.** 공단 표본 실측("몇 배 동반")과 임상 지식("왜 같이 나타나는가")을 같은 무게로 보여주지 않는다.
2. **재현성 ≠ 효과크기.** 재현성이 좋아도 약한 효과는 내세우지 않는다(지우지는 않는다).
3. **기존 문구를 부정할 때는 독립된 근거 2건 이상**을 요구한다(표본 하나로 뒤집었다가 틀린 적이 있다).
4. **판정·수치 계산·우선순위·또래 통계는 LLM에 넣지 않는다.** 분석 경로에 LLM은 0건이고(Gemini는 OCR에만), 같은 입력엔 항상 같은 출력. 이 앱의 철학은 "모든 문장에 출처를 붙인다".
5. 개인화 전수 감사 결과: 판단·문구 생성 지점 42개 중 29개는 이미 개인 값에서 나옴("그대로 두기"), 문구만 하나인 것 7, 규칙을 만들 것 3, 한 줄 고칠 것 2, 죽은 출력 1. **①층(기준 판정)과 ③층(또래 비교)은 이미 개인화돼 있으니 건드리는 제안은 거절**한다.
6. "데모/예시 데이터" 고지는 지우지 않는다(심사 인상을 이유로 지우는 것은 이 앱의 서 있는 자리와 어긋남).
7. 계산기 결과가 학회 기준이 없는 지표(TyG·AIP 등)는 또래 분포가 유일한 좋고 나쁨의 근거다 → 등수 자체는 필요.

## 10. 팀 작업 규칙과 함정

- **문서가 두 곳에 있다**(저장소 `docs/design/` ↔ `WITHUS/정리/NN_…`). 디자인 작업이라 의도적 중복이고 **고칠 때 양쪽을 함께** 고친다. 한쪽만 고치면 조용히 갈라진다.
- **카드 이름을 바꿀 때**: `cardContent`의 키가 곧 카드 제목이라 tsc가 못 잡는다. 어긋나면 ②④⑤가 조용히 빈칸이 된다. 바꾼 뒤 스펙 §2-1에 있는 키 대조 스크립트를 돌린다.
- **JSX 연산자 우선순위**: `{A || B && <X/>}`는 괄호를 쳐야 한다(A가 참이면 아무것도 안 그림). JSX 속성 자리에 `{/* */}` 주석을 쓰면 TS1005.
- **`plain` 같은 선택 필드는 tsc가 누락을 못 잡는다** → `calcPlain.test.ts`가 있/해요체/원문 비복사/약어·컷오프 숫자 누출을 강제한다.
- **큰 재작성 뒤에는 전후 렌더 필드를 기계적으로 대조**한다(`unchanged` 블록이 조용히 빠졌던 일).
- **화면이 안 바뀌면**: ① Metro의 작업 디렉터리 ② 번들을 직접 받아 grep ③ `adb reverse --list`에 Metro 포트가 있는지. 큰 변경 뒤엔 Fast Refresh를 믿지 말고 앱을 완전히 재시작. (Metro가 다른 브랜치를 서빙하거나 내장 APK를 보고 있던 사례가 반복됨)
- **APK**: Expo Go에서는 안 드러나는 버전 불일치(`expo-font`)가 APK에서만 터진다. Windows 경로 260자 제한 때문에 `C:\hab`로 복사해 빌드한 이력.
- **추측으로 낸 처방은 거듭 뒤집혔다.** 코드·데이터를 열어 본 뒤에 말한다. 재현 경로를 좁혀도 "어느 화면인지"는 사용자만 안다 → 먼저 묻는다.
- **브랜치**: 문서는 `design-b`(최종 태그 `design-b-final-2026-08-03`)가 최종안이라 하고 `main`의 `ee39dfc`는 같은 지점에서 갈라진 다른 시도라 한다. **현재 폴더는 `design-improve`**이므로 어느 브랜치가 어떤 상태인지는 직접 확인이 필요하다.
- 데모 계정은 `root` / `1234`. `.env`가 없으면 데모 모드로만 동작한다.

## 11. 시니어 관점에서 부딪히는 곳

> 이 절은 팀 문서가 아니라 **우리가 시니어 앱 디자인 기준과 토큰을 대조한 해석**이다. 대비 비율은 위 토큰 값으로 직접 계산했다.

| 항목 | 팀 기준 | 시니어 권장 | 판단 |
|---|---|---|---|
| 글자 크기 | 문장 13 / 캡션 11 / 배지 10 | 본문 16 이상, 가능하면 18 | **충돌** (의도된 결정이지만 기준이 정보 밀도였지 시니어가 아니었음) |
| 텍스트 대비 | `T.text3` `#8B95A1` | 4.5:1 이상 | 흰 배경 3.0:1, 앱 배경 2.8:1 → **미달** |
| 배지 글자색/틴트 | 주의 `#D97706`/`#FFF3E7` 등 | 4.5:1 이상 | 주의 2.9, 위험 3.2, 정상 3.9 → **미달** |
| 버튼 흰 글자 | 흰색 / `#00C073` | 4.5:1 이상 | 2.4:1 → **미달** |
| 본문색 | `#4E5968` / 흰 배경 | 4.5:1 이상 | 7.1:1 → 충족 |
| 터치 높이 | 버튼 최소 48 | 44\~48 이상 | 충족 |
| 색만으로 구분 금지 | 배지에 텍스트 병기 | 일치 | 충족 |
| 쉬운 말·해요체·용어 뒤로 | 핵심 원칙 | 일치 | 충족 |
| 한 화면 한 가지 | 홈만 토스 밀도, 나머지는 뱅샐 밀도 | 한 화면 한 가지 | 부분 충돌 (스펙 §8이 "항목 20개 리스트에 부적합"이라며 의도적으로 채택 안 함) |
| 터치 간격 | 정의 없음 | 8dp 이상 | 미확인 |

**주의**: 글자 크기 하한은 같은 팀이 "규칙 쪽이 틀렸다"고 명시적으로 개정한 항목이다. 되돌리자고 할 때는 그 근거(항목 17개 화면)를 알고 제안해야 한다. 가능한 방향은 (a) 사용자 설정으로 글자 크기를 키우기, (b) 시니어에게 특히 중요한 1뎁스 결론·버튼만 먼저 키우기, (c) 전체 하한을 올리고 밀도를 포기하기 — 어느 쪽이든 팀 결정 사항이다.
