## 1. 세어 보니 두 칸이 비어 있었다

층은 기능별(판정→계산→비교→행동)로 짜여 있는데, 데이터 종류 × 기능으로 세면 이랬다.

| | ① 판정 | ③ 또래 비교 | ④ 행동 |
|---|---|---|---|
| 단순 수치 | ✅ | △ 검사항목 탭에만 | ✅ |
| 단일 그룹 | ✅ | △ 7/13 | ✅ |
| 조합그룹 | ⚠️ O/E는 위험도가 아님 | ✅ | ❌ **없음** |
| 계산 수치 | ✅ | △ 5/15 | ❌ **고정 문구** |

## 2. 만들어 놓고 안 닿던 것 — 딕셔너리 6줄

원자료를 다시 돌려야 하는 줄 알았는데, **데이터는 이미 다 있었다.**

```
calculator_percentiles_2017.parquet  10종  ↔  KEY_TO_INDICATOR  5종만 매핑
single_groups_16yr.parquet           13종  ↔  _TREND_GROUPS     7종만 통과
```

- **계산기 또래 5 → 10종** (Non-HDL·Castelli I·II·De Ritis·MAP)
- **단일그룹 또래 7 → 8종** — `g_pre_hypertension`만 더한다. 당뇨 전단계는 있는데
  고혈압 전단계만 빠진 누락이었다.

**흡연 3종·음주 2종은 일부러 넣지 않았다.** 문진 기반 «행동»이라 「또래 100명 중
32명이 흡연해요」가 판단을 돕기보다 **「나만 그런 게 아니네」로 읽혀 행동을 막는다.**
유병률은 상태를 상대화할 때 쓰는 것이지 행동을 상대화할 때 쓰는 것이 아니다.

### 컷오프가 있는 지표에 또래를 달 때

새로 매핑한 5종은 **컷오프가 있는** 지표다. 그래서 또래는 판정을 대신하지 않고 **보조**로만
쓴다 — 결론은 학회 기준이 말하고 백분위는 그 아래 작은 줄이다. 「또래 평균 근처면
괜찮다」로 읽히면 ③층 「또래 자체가 나빠졌나」가 경고하는 바로 그 오독이 된다.

## 3. 조합그룹 → 행동

조합이 개별 판정에 더해 주는 것은 **두 항목의 관계**다. 관계를 알면 순서가 나온다 —
같은 원인이면 하나만 잡아도 둘이 움직이고, 다른 축이면 따로 잡아야 한다.
기록 36 §4-2의 설계대로 12개를 네 유형으로 묶었다.

| 유형 | 뜻 | 예 |
|---|---|---|
| `same_cause` | 같은 원인에서 함께 나옵니다 | 비만+지방간 — 내장지방이 둘을 같이 만들어요 |
| `one_worsens` | 하나가 다른 하나를 밀어붙입니다 | 음주+지방간 — 절주가 첫 순서예요 |
| `different_axis` | 서로 다른 축이라 위험이 곱해집니다 | 고혈압+이상지질 — 하나만 잡으면 다른 하나는 그대로 |
| `shared_criterion` | 판정 항목을 공유합니다 | 대사증후군+비만 — 허리 하나가 둘을 같이 움직여요 |

## 4. 계산기 → «내 값» 기반 행동

카드 ⑤가 「TyG가 높으면 체중·탄수화물 관리가 우선이에요」였다. **TyG가 낮아도 똑같이
나오는 고정 문구**다(기록 36 #8).

각 입력을 또래 중앙값으로 바꿔 보면 어느 쪽이 기여했는지 정확히 나온다. 기여도는
공식의 형태에 맞춰 같은 자로 잰다:

| 계산기 | 공식 | 기여도를 재는 자 |
|---|---|---|
| TyG | `ln(TG) + ln(FBS) − ln2` | 로그 차 (정확히 더해진다) |
| Non-HDL | `TC − HDL` | mg/dL 차이 (HDL은 부호 반전) |
| AIP | `log10(TG/HDL)` | 비율의 로그 |
| MAP | `(SBP + 2·DBP)/3` | 가중치를 곱한 mmHg |

```
TG 189 / FBS 105  → 「중성지방 쪽이 이 값을 더 끌어올렸어요」
TG 100 / FBS 130  → 「공복혈당 쪽이…」
정상 범위          → None (지어내지 않는다)
```

1위가 2위의 1.5배 미만이면 «둘 다»로 말한다 — 근소한 차이를 단정하지 않는다.
`driver_metrics`(끌어올린 수치 이름)도 함께 내려보낸다 — ④층이 문장을 다시 파싱하지
않고 «그 수치를 움직이는 행동»에 근거를 붙이는 데 쓴다.

## 5. 조합그룹을 다시 본 것 — 사용자 지적에서 시작

「조합그룹은 그냥 찾아낸 규칙 아닌가, 검증에서 대부분 못 쓴다 하지 않았나,
우리가 멋대로 의미를 부여하는 것 아닌가, 애초에 필요한가」

증거를 확인했다. **셋 중 하나는 지적이 맞았다.**

| 물음 | 확인 |
|---|---|
| 규칙 마이닝인가 | **아니다.** 임상적으로 고른 12개에 동반빈도를 잰 것. 순서가 반대 |
| 검증에서 대부분 탈락했나 | **아니다.** 버린 것은 조합이 아니라 «연도»다(2026-07-29 재분석 §3-B) |
| 멋대로 의미를 부여했나 | ✅ **맞다.** `relation`·`action`은 임상 지식으로 쓴 상수인데 화면이 O/E와 같은 무게로 보여줬다 |

### 고친 것

**① 결론을 바꿨다.** 「흔한가」는 답을 알아도 할 일이 안 바뀌고(축 0 판별 테스트),
바로 위 「나 같은 사람이 얼마나 되나」와 **화면에서 같은 질문으로 읽혔다.**

```
전  이 조합이 흔한가 — 조합 4개 · 같은 조합인 사람은 100명 중 10명이에요
후  함께 움직이는 게 있나 — 2개 조합 중 1개는 하나를 잡으면 함께 움직여요
```

**② O/E를 결론에서 «근거»로 내렸다.** 사라지지 않는다 — 「왜 이 둘을 같이 보라는
건가」의 답이 되어 오히려 제 역할을 한다(§1-1 자산은 죽이지 않는다).

**③ O/E 1.5 미만은 행동으로 내세우지 않는다** (12→8, 화면상 4→2).

```
당뇨+고혈압+이상지질혈증  2.93        고혈압+이상지질혈증  1.37  ← 아래는
비만+이상지질+지방간      2.67        대사증후군+흡연      1.32     내세우지
…  당뇨+이상지질혈증      1.53        비만+당뇨전단계      1.24     않는다
                                      음주+지방간의심      1.15
```

**재현성과 효과크기는 다르다.** 1.15는 «재현성 있게 약한 것»이다. 지우지는 않고
근거 목록에 값과 함께 남기고, 왜 뺐는지 화면이 밝힌다.

**④ 출처가 둘이라는 것을 화면이 말한다.**
> «몇 배 동반»은 공단 표본에서 센 값이고, «왜 같이 나타나는지»는 임상 지식에 따른 설명이에요.

### ⚠️ 층은 ④로 옮겼다가 ③으로 되돌렸다

한 번 ④층으로 옮겼다(`d2aa3c6`). 「관계 → 순서」는 또래 이야기가 아니라 행동
이야기라는 논리였다. 그런데 사용자가 「그냥 ③으로 가는 게 낫다」고 해서 되돌렸고
(`d2f0f39`), 대신 **③에 또래 비교를 모으는 것**으로 층 문제를 풀었다(§6).

## 6. 층 이름이 거짓말을 하고 있었다

사용자 지적 — 「단일그룹·조합그룹·단순수치는 왜 ③에서 안 해줌?」

세어 보니 맞다. **분석 탭의 층은 기준이 둘로 섞여 있다.**

```
① 기준을 벗어났나           ← 데이터 종류 (검진 수치·그룹)
② 검진지에 없는 값을 만들어요  ← 데이터 종류 (계산기)
③ 같은 또래는 어떤가         ← 기능 (비교)
④ 그래서 뭘 하면 되나        ← 기능 (행동)
```

기준이 둘이라 겹치고, 그래서 또래 비교가 ③에 모이지 못하고 흩어졌다:

| 또래 비교 | 있던 곳 |
|---|---|
| 단순수치 17종 | ①층 항목 줄 |
| 단일그룹 8종 | ①층 상태 줄 |
| 계산기 10종 | ②층 각 카드 |
| 관리참고군 분포 · 16년 변화 | ③층 ← **여기 두 장뿐** |

**「같은 또래는 어떤가」라는 층에 정작 또래 비교가 두 장밖에 없었다.** 사용자가
「또래와 견준 걸 보고 싶다」고 ③에 오면 못 찾는다. 층을 기능으로 나눠 놓고 그 기능을
다른 층에서 하면 층이 장식이 된다.

### 해법은 옮기는 것이 아니라 «겹치는» 것 (팀 결정)

판정 옆의 한 줄(「고혈압 해당 / 또래 100명 중 32명」)은 그 판정을 읽는 **맥락**이고,
③의 모아 보기는 「내가 또래 중 어디쯤인가」라는 **다른 질문**이다. 읽는 목적이 다르면
같은 데이터를 두 번 써도 «같은 말 두 번»이 아니다 — 기록 39가 장기 구획
(「신장 / 콩팥이 잘 거르고 있나」)에서 내린 판단과 같다.

**③-0 「또래 중 어디쯤인가」 신설:**

```
검진 항목 14개   감마-GTP 80등 · LDL 78등 · 수축기 75등 …   (나쁜 순, 어림이면 표시)
해당 상태 5개    대사증후군 29명 · 이상지질혈증 37명 …       (드문 순)
계산 지표        기준 연도를 함께 밝힌다(지질은 2017 고정)
```

## 7. 또래 비교의 기준연도 — 2017 고정은 의도였다

`calculator_percentiles_16yr.parquet`(4,392행)이 참조 0건이라 조사하다 더 큰 것이
나왔다. **계산기 또래가 2017 한 해로 고정**돼 있었다. 2024년 검진을 2017년 또래와
견주는 셈인데, ③층이 「16년 새 비만 21%→46.1%」라고 말하는 앱에서 그냥 넘길 일이 아니다.

그런데 **2017 고정은 실수가 아니라 의도**였다. 2018년 지질검사 4년주기 전환 이후
지질을 잰 사람만 분모에 들어가고, 그 부분집합은 이미 관리 중인 쪽으로 쏠려 있다.
표본 수로도 보인다:

```
2024년 · 남 55~59세   TyG 16,295 · Non-HDL 16,307   ← 지질: 1/3만 측정
                      De Ritis 50,466 · MAP 50,466  ← 전수
```

그래서 갈랐다. **전수 측정되는 De Ritis·MAP만 검진 연도**로 견주고(16년 파일 사용,
그 해가 없으면 최근접), 지질 기반 8종은 2017 고정을 유지한다. 어느 해 기준인지는
`peer_year`로 화면이 밝힌다.

### 데모 백분위도 같은 실수를 했다

항목별 백분위를 뽑을 때 내가 `year=2017`로 고정했다. 실서비스는 검진 연도를 넘긴다
(`compare_to_peers` 기본값 2024). 8개 회차를 당해연도 기준으로 교체했고, 2008년은
`peer_stats`가 2009년부터라 실측이 없어 「(어림)」으로 뒀다.

## 8. ④층 — 행동이 다섯 번 나오는데 «뭘 먼저»가 없었다

「금연」 하나가 분석 탭에서 이렇게 나왔다:

| 어디 | 문구 |
|---|---|
| ④ 맞춤 권장사항 | 흡연은 모든 대사증후군 인자를 악화시킵니다 |
| ② 심혈관 ⑤ | 금연이 단일 항목 중 가장 크게 위험을 낮춰요 |
| ③ 조합 ⑤ | 대사 쪽과 혈관 쪽이 겹쳐 위험이 곱해져요… |
| ② 심혈관 ③ | 금연했다면 8.9% (−6.8%p) |
| ④ 목표 세우기 | `quit_smoking` 행동 |

**다섯 번 말하는데 «그래서 금연부터 하라»고는 아무도 말하지 않았다.** ④층 이름이
「그래서 뭘 하면 되나」인데 정작 «뭘 먼저»가 없었다.

### ④-0 「무엇부터 하면 되나」 신설

행동을 새로 만들지 않는다 — **모아서 순서를 매긴다.** 문구는 전부 기존 것 그대로(§2-1).
순서는 `rankActions`(기준 이탈도 감소폭)이고, 「목표 세우기」 모달과 같은 계산을 쓴다 —
한 화면에서 두 곳이 다른 순서를 말하면 안 된다.

```
3  술 끊거나 주 20잔 이하로 줄이기   −14%   움직이는 기준: 혈압 · 중성지방
   · AIP — 중성지방과 낮은 HDL이 비슷하게 끌어올렸어요       계산 지표
4  담배 끊기                        −9%
   · 셋이 서로 다른 경로라 하나씩 줄여야 해요                조합 · 흡연+음주+비만
   · 심혈관 10년 위험이 15.7% → 8.9%로 내려가요              심혈관 시뮬레이션
```

### 맞춤 권장사항 — 2뎁스가 통짜 글이었다

「권장사항 전체 보기」 하나에 공통 5묶음 + 항목별 조언이 12pt 불릿으로 **37줄** 쏟아지고,
정작 **내 값과 목표의 거리**는 그 사이에 묻혀 있었다. §2-1 그대로 다시 갈랐다.

| 층 | 담는 것 |
|---|---|
| 2뎁스 | **목표까지 얼마나 남았나 5가지** — 「지금 134/85mmHg — 목표까지 수축기 4 · 이완기 0 남았어요」 |
| 2.5뎁스 | **무엇을 하면 되는지 37가지** — 조언 문장 전부 |

거리는 읽으면 바로 행동을 정할 수 있고, 조언 문장은 그 뒤에 읽어도 된다.

### 행동 카드의 ②·④ 칸 제거

행동 카드는 지표 카드가 아니라 ②정의·④의미가 제목을 되풀이하고 있었다.

⚠️ **「무엇부터 하면 되나」의 ④만은 남겼다 — 자리를 옮겨서.** 「순서는 수치를 얼마나
움직이나로 매긴 것이지 **의학적 우선순위가 아니에요**」는 오해 차단이고, 1번에
「유산소 운동」이 뜨는데 그걸 «가장 급한 것»으로 읽으면 위험하다. 칸은 없애되 문장은
맨 밑 회색 줄(`footer`)로 옮겼다 — 심혈관 한계와 같은 처리.

## 9. 곁들여 고친 것

| 무엇 | 내용 |
|---|---|
| 크레아티닌 밴드 문구 | 「정상 **기관 기준 확인mg/dL**」 → 숫자가 있을 때만 단위를 붙인다 |
| `simulateDemo` 성별 | 허리 90·HDL 40 고정 → `gender`로 85/50 분기. 같은 화면 `MS_CRITERIA`가 이미 성별 분기가 있어 **여성이면 두 계산이 갈라졌다** |
| 항목별 또래 실측 | 데모가 전부 「(어림)」이었다 → 실측으로. 근사가 실제보다 나쁜 쪽으로 치우쳐 있었다(BMI 82→64등) |
| 백엔드 조사 처리 | `_josa()` 신설. 「이완기혈압와 수축기혈압가」가 나왔다(기록 36 §7-6) |
| 「계산기 22종」 문구 | **실제는 23종.** `additional_calculators`는 이력상 14→15였고 22였던 적이 없다. 셀 수 없는 자리의 숫자를 뺐다 |
| `hitSlop` | 12 → 36곳. 터치면적이 이미 큰 것(카드·칩)은 대상에서 뺐다 |
| `Collapsible` | 사용처 0건. 지우지 않고 «새로 쓰지 말 것, Expandable을 쓸 것» 주석만 |

### 글자 크기 조항 개정 (§7)

「본문 16 미만 금지」였는데 실측하면 16 이상은 약 50곳뿐이고 본문 대다수가 13\~15다.
**§8이 스스로 「L1부터 뱅샐 밀도」라고 적어** 두 조항이 부딪히고 있었다. 검진 항목이
17개인 화면에서 16pt 본문은 애초에 담기지 않는다 — **규칙 쪽이 틀렸다.**

| 역할 | 하한 |
|---|---|
| 읽는 문장(①결론·②정의·④의미·⑤행동) | 13 |
| 보조 캡션(근거·출처·한계·단위) | 11 |
| 배지·칩 라벨 | 10 |

가르는 기준은 «문장인가»다.

### ⚠️ 확인이 막혀 있던 이유 — Metro가 다른 브랜치를 서빙

작업 내내 화면에 변경이 반영되지 않았다. 기록 36 §7-8의 재발이고 원인이 둘이었다.

| 확인한 것 | 결과 |
|---|---|
| 8081 Metro의 작업 디렉터리 | `Health_Management_Service/frontend-mobile` = **`main` 브랜치** |
| 그 Metro가 내주는 번들 | 「간이 굳어가고 있나」 **0건** |
| 에뮬레이터의 `adb reverse` | `tcp:8095`·`tcp:8000`만 — **8081이 없다** |
| 설치된 앱 | Expo Go + **내장 APK** |

즉 보이던 화면은 예전에 design-b로 빌드된 **내장 APK**였고 Metro는 연결돼 있지도 않았다.

**다음에 화면이 안 바뀌면 이 순서로 볼 것:**

```bash
# 1) Metro의 «작업 디렉터리»부터 (바이너리 경로는 근거가 안 된다)
# 2) 번들을 직접 받아 바뀐 문자열을 grep
curl -s "http://localhost:PORT/index.bundle?platform=android&dev=true&minify=false" | grep -c "바뀐 문자열"
# 3) adb reverse에 Metro 포트가 있는지 / 어느 앱이 떠 있는지
cd worktrees/design-b/frontend-mobile && npx expo start --port 8083
adb -s emulator-5558 reverse tcp:8083 tcp:8083
adb -s emulator-5558 shell am force-stop com.anonymous.healthagemobile
adb -s emulator-5558 shell am start -a android.intent.action.VIEW -d 'exp://127.0.0.1:8083' host.exp.exponent
```

Expo Go는 작업이 없어 재시작할 때마다 로그아웃된다 — 데모 계정 `root` / `1234`.

### 이 작업에서 세운 규칙 (스펙 §2-1)

1. 근거의 «출처»가 둘이면 화면이 갈라 말한다
2. 재현성 ≠ 효과크기 — 약한 것은 내세우지 않는다(지우지는 않는다)
3. 1뎁스 결론이 옆 카드와 같은 질문을 하면 안 된다
4. 층이 «기능»이면 그 기능은 그 층에 있어야 한다 — 다만 읽는 목적이 다르면 겹쳐도 된다
5. 여러 지표를 담은 카드는 ②가 못 덮는다 — 지표마다 뜻풀이
6. 카드 전체에 걸리는 한계는 ⑤ 다음(`footer`)
7. 1뎁스 결론은 «답»이지 «값»이 아니다
8. 등수는 «대표 지표»로 말한다
