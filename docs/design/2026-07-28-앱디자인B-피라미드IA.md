## 2. 무엇을 했나

### 2-1. 정보 구조 — 3층 피라미드 (A안과의 핵심 차이)

```
L0 홈        건강점수 히어로 + "지금 주의할 항목 TOP 3" 카드(1·2·3 번호, 수치 없음, 해석 문장+배지)
  ↓ 하단 탭 (홈 '전체 항목 보기'도 이 탭으로)
L1 검사항목   연도 칩 + 상태 요약 필터 칩(정상 n·주의 n·위험 n) + 주의 순 정렬 리스트
             행 = 스쿼클 아이콘+항목명+값+배지+chevron (설명·정상범위는 L1에 없음)
  ↓ 항목 클릭 → 풀스크린 오버레이 (화면 전환은 여기 한 번만, Android 백버튼 처리)
L2 상세      쉬운 문장 헤드라인("공복혈당이 살짝 높아요") + 전년 대비("2022년보다 5mg/dL 올랐어요")
             + 또래 등수 슬라이더(percentile 있을 때만) / 정상범위 위치 바(없을 때 — 추정치 금지)
  ↓ '자세히 보기' 펼침 (화면 전환 아님)
L3 원본      원본 수치·정상범위 표 · 연도별 추이 차트(정상 밴드 배경, 최신 값 강조) · 용어 설명
             + 고지 "참고용이며 진단이 아닙니다"
```

- **탭 구성**: 처음엔 5→4로 줄였다가(히스토리 제거) **사용자 지시로 5탭 복귀** — §2-3 참조. 최종 = `홈 · 검사항목 · 히스토리 · 분석 · 업로드`.
- **기록 탭 → 검사항목 탭**: 연도 세로 리스트 → 가로 연도 칩. 기록 삭제 기능 보존. 복용약 세그먼트 그대로.
- **PDF 내보내기 → 프로필로 이동** (연도 칩 + 내보내기 카드, reports 없으면 미표시).
- **업로드**: 단계별 주 버튼을 하단 고정 CTA로, OCR 대기는 "결과지를 읽고 있어요" 로딩 카드로.

### 2-3. 히스토리 탭 복원 — 4탭 → 5탭 (Task 12, 작업 후반 사용자 지시)

> 사용자: **"굳이 히스토리를 분석 탭에 나눠 넣은 이유가 없는 것 같아 — 디자인을 유지하며 5개의 탭으로 복귀."**

Task 8의 통합을 **되돌렸다**(디자인 v2는 그대로 유지):

| 항목 | Task 8 (통합) | Task 12 (복원, 최종) |
|---|---|---|
| 탭 | 4개 (홈·검사항목·분석·업로드) | **5개 (홈·검사항목·히스토리·분석·업로드)** |
| 인사이트 카드 3종 | 분석 탭 상단으로 이식 | **히스토리 탭으로 원위치** (원래 자리) |
| 분석 탭 | 자기 콘텐츠 + 이식분 | Task 8 이전 상태(자기 콘텐츠만)로 복귀 |
| HistoryScreen.tsx | 삭제 | 복원 + **v2 리스킨** |

- **검사항목 탭은 v2 그대로 유지**(기록으로 되돌리지 않음) — L1 리스트가 피라미드의 핵심이라서.
- **L2 상세의 항목별 추이 차트(`MetricTrendChart`)는 그대로 둠** — 히스토리 탭은 그룹 단위 비교, L3는 단일 항목 상세로 역할이 다르다(중복 아님).
- 복원 시 v2 리스킨: 페이지 타이틀 34→**26**, `ChartCard`의 상태 테두리(`borderWidth 1.5`) 제거 → **"주의/위험 포함" 배지를 상태 틴트 배경**으로 전환(무테두리 원칙), 로컬 중복 `FadeInUp` 제거하고 UI.tsx 것 사용, 잔여 hex `#EFEFEF`→`T.cardAlt`.
- 데이터 로직은 삭제 직전 원본과 동등(연도 미측정 항목 제외 처리·범례·차트 수학 그대로) — 리뷰가 바이트 단위로 대조 확인.

## 4. 판정 기록 (사용자 확인용)

1. **홈 TOP3 카드에서 항목명이 두 번 보임** — 제목 "체질량지수(BMI)" + 해석 문장 "체질량지수(BMI)가 많이 높아요". 스펙 문장 포맷(항목명 포함)을 그대로 쓴 결과. 거슬리면 홈 카드에서만 주어 생략 가능 — **채택 결정 후 다듬을 것**.
2. **percentile 없는 항목은 등수 대신 정상범위 바** — "추정치를 지어내지 않는다" 원칙(데이터 정직성, 24\~26번 계열과 동일). 현 더미/실데이터 모두 percentile이 드물어 **대부분의 항목이 바로 표시됨**. 등수 슬라이더를 살리려면 §7-3 백분위 계산이 필요.

### 11-0. 설계 의도 (사용자 원안)

### 11-1. 1뎁스 판정 기준을 좁힌 것 (중요)

처음엔 1뎁스에 **①뭔지 ②내 상태 ③뭘 하면 되는지** 3요소가 필요하다고 봤으나, 사용자 지적으로 **③을 뺐다**:

> "뭘 하면 되는지는 라이트 유저가 굳이 알려고 하지 않는데 1뎁스에 표현할 이유가 없을듯"

→ 맞는 지적. **행동은 이미 관심이 생긴 사람의 정보**이고, 원안에서도 2-5(2뎁스) 소속이었다. 홈에 행동 한 줄을 넣자는 제안은 철회.

또한 ①정의도 **"뻔한 건 생략, 모를 만한 것만 아주 짧게"**로 좁혔다:

> "이게뭔지도 엄청 자세히는 2뎁스, 1뎁스는 뭔지 알만한건 넘기고 모를만한건 아주간단히"

**최종 기준: 1뎁스 = ①(모를 때만, 10자 이내) + ②**

| 히스토리 | △ 변화만 | ❌ 현재 판단 없음 | **수정함** |
| 분석 | ❌ 전문어 | △ | 하드 유저 전용이라 의도된 것 |

**검사항목 수정** — 카테고리(왼쪽 아이콘 색과 중복)를 빼고 `metricGloss`(신규, data.ts) 10개만 표시:
- 설명 **없음**(이름이 곧 설명): 허리둘레·수축기/이완기 혈압·공복혈당·총콜레스테롤·키·몸무게
- 설명 **있음**: BMI「키·몸무게 비만도」 LDL「나쁜 콜레스테롤」 HDL「좋은 콜레스테롤」 중성지방「혈액 속 지방」 AST·ALT「간 효소」 감마GTP「간·음주 효소」 혈색소「산소 운반 능력」 크레아티닌「신장 노폐물」 요단백「소변 속 단백질」
- ⚠️ **10자 초과 시 잘림** — 값·배지가 오른쪽 폭을 쓴다. 첫 시도(14자)에서 "비만…"으로 잘려 재작성.
- 중간에 `headline()`(=②상태)을 넣었다가 **배지·수치와 중복**이라 되돌림 — ①과 ②를 혼동한 실수.

**히스토리 수정** — `groupSummary()`가 변화량만 말하고 끝나던 것을 **현재 판단까지** 붙임: "2014년 이후 수축기가 22mmHg 올랐어요. **지금은 주의가 필요한 항목이 있어요.**"

### 11-3. 히스토리·분석 → 2뎁스 오버레이 구조

**시행착오**: 처음엔 카드 인라인 접기(`ExpandableCard`)로 만들었으나 사용자 지적 — "1뎁스로 압축하라는 게 아니라 **2.5나 3뎁스로 만들라는 말**". 즉 **눌러서 들어가는 화면**이어야 했다.

→ `SummaryCard`(v2.tsx 신규, 히스토리·분석 공용)로 교체:
- 1뎁스: 제목 + 결론 한 줄 + 배지 + `>` 쉐브론
- 2뎁스: 검사항목 상세와 **같은 규격의 전체화면 Modal** — ①결론 헤드라인 → ②이 지표는요(+2.5뎁스 「자세히 알아보기」) → ③나의 위치(등수+근거) → ④그래서 이게 의미하는 건 → ⑤그럼 뭘 하면 좋을까요
- props: `definition` / `detail`(2.5뎁스) / `meaning` / `tips` / `positionTitle` / `positionExtra`

**콘텐츠 20카드 신규 작성** (`cardContent` in data.ts, 카드 제목이 키):
히스토리 7(차트 5그룹 + 또래 변화속도 + 주목할 변화) · 분석 13(참고군 5 + eGFR·지방간·간계산기·대사지질·LDL목표·조합·집단군·ASCVD·권장사항)

관리 참고군도 인라인 펼침 → `SummaryCard`로 전환. 그 과정에서 쓰이지 않게 된 `expandedGroup` state와 `useEffect` import 제거.

### 11-4. "100명 중 몇 등" 그래프

정상범위 바와 **별도 그래프**로 분리(사용자 요청). 등수 출처 2가지:
- **실측**: 백엔드 `percentile`(계산기 5종 — TyG·METS-IR·AIP·LAP·VAI, 2017 국가검진 100만명). percentile은 누적분포라 값이 클수록 나쁜 지표에서 그대로 등수가 됨.
- **추정**: `estimateRank()`(interpret.ts 신규) — 또래 평균을 중심으로 **정상범위 폭의 1/4을 SD로 가정**한 정규분포 근사(정상범위 ≈ 평균±2SD 관행). 로지스틱 근사로 Φ(z) 계산(의존성 없이 오차 <1%p). HDL처럼 높을수록 좋은 항목은 방향 반전 → **1등 = 항상 가장 좋음**. 화면에 "어림한 추정 등수예요" 명시. 테스트 4개 추가.

**슬라이더 10등분** — 점 하나면 "어디쯤"이 눈대중이 되므로 10칸으로 나누고 **내가 속한 칸만 상태색**. 하단에 "상위 61\~70등 구간" 라벨.

적용: 검사항목 상세 · 히스토리 그룹(가장 나쁜 항목 기준) · 분석 참고군/계산기.

### 11-5. IA 논의 — 결론: 변경 없음

히스토리 탭 필요성을 감사한 결과 **고유 자산은 "또래 대비 변화 속도" 하나**뿐이고 나머지는 중복(차트=항목 상세에 이미 있음, 한눈에 요약=홈 성격, 항목별 설명=상세와 완전 중복)이었으나 —

**팀 결정: 히스토리 유지 · 5탭 유지** ("메뉴탭이 5개여야 안정감있고 좋을거 같은데"). 4번째 정보탭 논쟁은 종결.

### 12-2. 계정별로 돌아가는 기능이 다르다 (App.tsx 게이팅)

앱은 3단계로 갈린다. `usingRealData = 실계정 && 검진기록 ≥1`, `isDemoAccount = root/1234`.

| 기능 | 미로그인 | root(데모) | 실계정+기록 |
|---|---|---|---|
| 관리 참고군 / 조합 / 집단군 / 계산기 | 프리뷰 | ✅ 더미 | ✅ 실데이터 |
| **eGFR·CrCl (신장 도메인 전체)** | ❌ | **❌ 항상 null** | ✅ (크레아티닌 있을 때만) |
| **What-If 시뮬레이터** | ❌ | **❌ 비활성 + 안내문구** | ✅ |
| **`rarity` 요약**(집단군 판정 1뎁스 결론) | ❌ | **❌ 더미에 필드 없음 → 부제 빈칸** | ✅ |
| 계산기 `unavailable` 목록 | — | ❌ 더미가 `[]` | ✅ |
| 검진기록 삭제 / 복약 실데이터 / 결과지 업로드 | ❌ | ❌ | ✅ |

`egfr={usingRealData ? egfr : null}` — 더미 대체가 없는 유일한 값이라 데모에서 🩺 신장 섹션이 통째로 안 뜬다.

### 12-3. 실계정에서도 데이터가 없으면 빠지는 것

지어내지 않는다는 원칙에 따라 입력값이 없으면 계산·표시를 건너뛴다.

- **eGFR** — 그 해 혈청 크레아티닌이 없으면 API 호출 자체를 안 함 → 카드 없음
- **CrCl** — 체중이 없으면 eGFR만
- **계산기** — 필요 항목이 없으면 `unavailable`로 (← ②로 이제 화면에 드러남)
- **조합** — 판정 불가 조합은 `not_evaluable`로 사유·부족항목 표시
- **ASCVD** — `available=false`면 카드 자체가 없음 (사유 미표시, 잔여 과제)
- **히스토리 하이라이트·변화속도·인사이트** — 기록 2년 미만이면 백엔드가 비워서 내려줌
- **지방간 유형** — 음주량(주당 순알코올) 없으면 `provisional=true` → "(잠정)" 표기

| '집단군 판정' 1뎁스 결론 빈칸 | 더미에 `rarity` 필드 자체가 없었음 | `single_groups`의 `applies:true`를 그대로 센 값(임상 6 · 생활습관 1)으로 추가 |
| What-if 버튼 잠김 | `POST /analyze/simulate`가 로그인 토큰 + 저장 검진회차를 읽음 → 데모는 호출 불가 | `simulateDemo()` 신설. **클라이언트에서 정직하게 셀 수 있는 것만** 재계산 |

**`simulateDemo`의 경계선** — 대사증후군 5개 기준은 고정 컷오프 비교라 백엔드 공식을 옮겨 적을 게 없다(같은 컷오프가 이미 `metabolic_syndrome_detail.reason` 문구에 적혀 있다). 반면 **계산기 22종은 서버 공식이라 다시 만들지 않고 비워 두고**, `limitations`에 "데모라서 못 한다"고 밝힌다. 지어낸 값을 보여주느니 못 한다고 말하는 쪽을 택했다.

에뮬레이터 확인: 허리 93→89 · 공복혈당 112→99 · 중성지방 178→148로 낮추니 **대사증후군 5→2 · "3개 미만이 되어 기준에서 벗어나요" · 남는 항목 고혈압·낮은 HDL · 집단군 변화 '벗어남: 대사증후군'** 이 정확히 나왔다.

**여전히 root에서 안 되는 것 (구조상 불가)** — 결과지 업로드·검진기록 삭제·복약 실데이터. 전부 서버 쓰기라 Supabase 작업이 없는 데모 계정에서는 성립하지 않는다.
`calculators.unavailable`은 데모 페르소나가 22종 전부 계산 가능해 빈 배열이다 — 버그가 아니라 "빠진 게 없어서 안 보이는" 정상 동작.

## 13. 히스토리 그래프 가독성 개선 + 기준 항목 연동 (07-29 밤)

### 13-1. 문제

사용자 지적 3건 + 감사에서 찾은 결함 1건.

| 문제 | 원인 |
|---|---|
| **정상범위를 그래프에서 알 수 없음** | Y축 눈금이 데이터에서 자동 계산된 임의값(154·122·90·58). 상태는 하단 범례 텍스트로만 전달 |
| **범례 색 불일치** | 스와치는 선 색(파랑)인데 글자는 상태색(주황) → 어느 선인지 매칭 끊김 |
| **동그라미 과대·겹침, 숫자 과다** | 계열마다 첫·마지막·선택 라벨 = 최대 12개 숫자가 선을 가림 |
| **아래 수치 목록 난잡** | "N년 검진 수치"와 "범례"가 **같은 항목을 두 번 나열** |
| ⚠️ **밴드가 거짓 정보를 줌** | LDL 밴드(0\~130)가 화면 절반을 덮어 HDL 39(주의)가 초록 띠 안에 들어감 |

### 13-2. 조치

- **정상범위 밴드** — 검사항목 상세 RangeBar와 같은 초록 띠(`NORMAL_BAND`)를 배경에 깔고 경계는 점선. 경계 숫자는 그래프 밖 캡션으로 뺐다(그래프 위 글자 하나 = 가려지는 선 하나).
- **포커스/디밍** — 밴드 주인 선만 진하게, 나머지는 `opacity 0.3`. 여러 계열이 한 축을 공유할 때 밴드가 남의 선까지 덮는 문제를 이걸로 막았다. 캡션에도 "진한 선만 이 띠로 판단하세요".
- **축** — 끝을 눈금 배수로 자르던 것(0\~300까지 늘어나 데이터가 가운데 뭉침)을 데이터에 밀착시키고, 눈금선만 `niceStep`(1·2·2.5·5·10 배수)으로.
- **점·숫자 감량** — 점 r 4→2.8(디밍 2), 선택만 4.5. 숫자는 **선택 연도의 포커스 계열 하나만**.
- **목록 통합** — 검진 수치 + 범례를 한 줄(색 막대·이름·값·상태점)로 합치고 세로 정렬. `ChartLegend` 함수 삭제.

### 13-3. "기준을 바꾸는데 나의 위치는 안 변함" — 연동 버그

칩은 `band`만 바꾸고 위쪽 등수 블록은 `leadMetric`(가장 나쁜 항목)에 고정돼 있었다.
→ **하나의 '기준 항목'이 밴드·포커스 선·등수를 모두 결정**하도록 묶었다. 칩 라벨도 `정상범위 기준` → `기준 항목`. 선택 칩 재탭으로 꺼지던 토글 제거(항상 하나 선택). `leadRank` 제거.

### 13-4. 남은 것

⚠️ `normalBounds()`가 `"남 11-63 / 여 8-35"` 같은 성별 분기 문자열에서 **첫 숫자쌍(남성)만 파싱**한다.
데모 페르소나가 남성이라 지금은 맞지만 **여성 사용자에게는 밴드가 틀리게 그려진다.** 성별 인자를 받도록 시그니처 변경 필요 — 미착수.

### 13-5. 데모 계정 셋업 (같은 작업)

- `frontend-mobile/.env` 신설 — Supabase 키(backend/.env의 anon) + `EXPO_PUBLIC_BACKEND_URL=http://10.0.2.2:8000`(에뮬레이터에서 127.0.0.1은 에뮬레이터 자신) + `EXPO_PUBLIC_ENABLE_DEMO=1`(Supabase 설정 시 데모가 자동 비활성되므로 명시 유지).
- 백엔드 기동 확인: 에뮬레이터 브라우저에서 `10.0.2.2:8000/health` → `{"status":"ok","users":4,"checkups_total":4}`.
- **HIRA 생일 401 막다른 길 수정** — 백엔드는 `manual_birthday`를 받도록 열어 뒀는데 `UploadScreen`이 넘기지 않아, 프로필 생일이 파일과 다르면 401로 끝나고 재입력 수단이 없었다. 400/401 시 **생년월일 8자리 모달 → 같은 파일로 재시도**하도록 `runMedUpload()`로 분리.
- ⚠️ OCR·복약 업로드 **실제 테스트는 미실시** — 실계정 로그인 정보와 검진지 사진이 없다.
