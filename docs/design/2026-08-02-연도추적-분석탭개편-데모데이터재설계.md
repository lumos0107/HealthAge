## 1. 연도 추적 — 차트만 최신에 고정돼 있었다

### 1-1. 사용자가 본 것

> "히스토리 탭에서 연도 바꾸고 상세 항목 클릭하면 연도에 따라 안 바뀌고 최신 것만 보임"

처음엔 히스토리라고 하셨고 나중에 **검사항목 탭**으로 정정하셨다. 그 사이에 히스토리
쪽을 고쳤다가 되돌린 왕복이 있었다 — 재현 경로를 코드로 좁힌 뒤에도 **어느 화면인지는
사용자만 안다**. 먼저 물었어야 했다.

### 1-2. 원인

`MetricTrendChart`가 «지금 보고 있는 해»를 **아예 받지 않았다.**

```ts
const last = pts[pts.length - 1];   // v2.tsx — 무조건 마지막 점을 강조
```

값·배지·헤드라인·전년 대비·등수는 전부 `report` 기준이라 처음부터 정상이었다.
**차트 하나만** 최신에 고정돼 있었다. 그래서 2018년 상세를 열면
「내 수치 23.9」 바로 아래에서 차트가 26.3(2024)을 큰 점으로 강조했다.

### 1-3. 고친 것

| | |
|---|---|
| `highlightYear` | **필수** 인자로 추가 — 기본값을 두면 같은 버그가 조용히 되살아난다 |
| L2 연도 칩 | 화면 안에서 해를 바꾼다(분석 탭과 같은 방식) |
| 연도 소유 | `App`의 `detail.year` 한 곳 — 상세가 따로 상태를 들면 목록과 갈린다 |
| 칩 목록 | `yearsWithMetric()` — **그 항목을 실제로 잰 해만** |
| 차트 탭 | 그래프를 눌러 그 해로 이동. 누른 x를 «측정한 해»로 스냅한다 |

마지막 항목이 핵심이다. 안 잰 해를 고를 수 있게 두면 그 해엔 판정이 없어
`metricsForReport`가 걸러내고 **상세 화면이 통째로 사라진다.** 이 함수만 TDD로 뽑았다
(RED 4개 → GREEN).

## 2. 분석 탭 개편 — 후보 8개 중 7개

사용자가 "1뎁스를 이해하기 쉽고 보기 좋게" 요청 → 후보 8개를 제시하고 되돌릴 수 있게
**영역이 겹치지 않는 세 커밋**으로 쪼갰다. 시작 전 태그를 찍었다.

### 2-1. 가장 큰 문제는 첫 화면이 아니라 «카드 13장이 평평한 것»이었다

```
간 계산기         지표 2개 모두 양호 구간이에요.
대사·지질 계산기   지표 7개 중 6개가 주의 이상 구간이에요.
```

제목은 전부 같은 검정, 요약문은 전부 같은 회색. **두 카드가 시각적으로 완전히 같았다.**
맨 위 결론이 "신장 기능부터 보세요"라고 말해도 아래에서 색으로 찾을 수 없었다.

배지 재료는 **처음부터 있었다** — 계산기마다 `level`을 들고 있고 `calcLevelColor`가
색까지 매핑하는데 2뎁스 안에서만 쓰고 1뎁스로 안 올렸다. 스펙 §1-1①("타입에만 있고
안 그리면 없는 것")의 사례가 하나 더 나온 셈이다.

### 2-2. 커밋 A·B·C

| 커밋 | 내용 |
|---|---|
| **A** `45cad05` | 결론 문장을 점수 카드로 이동 · 중복 부제 삭제 · 면책 하단으로 |
| **B** `d102ae1` | 판정 배지 7장 · 권장사항 요약 한 줄 · 소제목 「신장 기능」→「신장」 |
| **C** `8e746c4` | 요약문 — 상태는 배지에 넘기고 종결어미 제거 |

**세 가지 판단을 내렸고 근거를 남겼다.**

1. **낱말은 「양호·주의·높음」** — '위험'을 안 쓴다. 선별용 참고 지표(FLI·ASCVD)에
   진단 강도의 낱말을 쓰면 스펙 §7 "진단 단정 금지"에 걸린다
2. **관찰 카드에는 배지를 안 단다** — 집단군 판정·또래 분포·조합·16년 변화는
   판정이 아니다. 배지를 달면 백엔드가 하지 않은 판단을 앱이 만들어낸다
3. **LDL은 `achieved`가 null이면 배지 없음** — TG≥400이면 Friedewald LDL의 신뢰도가
   떨어져 판정 보류다. 모르는 것을 양호나 주의로 말하지 않는다

### 2-3. 하려다 만 것 — 근거를 남긴다

**① 걸린 지표의 «이름»을 요약문에 대려 했으나 포기했다.**
개수보다 이름이 유용하지만 항목명이 「Castelli 지수 I」·「AIP 죽상형성지수」·「METS-IR」
처럼 전문용어다. 1뎁스에 늘어놓으면 스펙 §2를 어기고 읽히지도 않는다.
**데이터를 열어보기 전에 드린 제안(#2 "최악 우선 — 가장 나쁜 건 중성지방 210")이
틀렸다.** 제안 전에 실제 값을 봤어야 했다.

**② 「지방간 유형」의 용어-우선 순서는 손대지 않았다.**
「MetALD 의심 (대사이상 + 유의한 음주 동반)」은 용어가 앞에 와서 MetALD를 모르면
문장 전체가 버려진다. `metricPlainName`·`groupSummary`가 쓰는 `쉬운 말(실제 용어)`
규칙과 반대다. 그러나 이 문자열은 백엔드 `fatty_liver.type`이 통째로 만들어 보낸
표시 문구라, 프론트에서 괄호를 파싱해 뒤집으면 백엔드 문구가 바뀌는 순간 깨진다.
→ **백엔드에 `plain` 필드를 두는 것이 맞다. 별건.**

### 2-4. 헤더는 네 번 만에 정리됐다

커밋 A에서 결론 문장을 내린 뒤 「이 화면은 무엇을 하나요?」만 여백에 떠 있었다.

| | 시도 | 왜 이상했나 |
|---|---|---|
| ① | 가운데 정렬 + 구분선 | 위에 가릴 것(결론)이 없어져 구분선이 제목과 버튼을 갈랐다 |
| ② | 왼쪽 알약 버튼 | 한 줄을 통째로 차지해 세로가 길고 오른쪽이 비었다 |
| ③ | 제목 옆 알약 | 「보는 법」이 오른쪽 끝에 떨어져 제목과 무관한 조각으로 읽혔다 |
| **④** | **설명 줄 자체를 버튼으로** | 히스토리와 머리 모양이 같아졌다 |

마지막에 한 가지를 더 배웠다 — **설명문만 두면 읽는 글로만 보여서 아무도 안 누른다.**
줄 끝 화살표 하나로는 약해서, 진한 글씨로 「분석 탭 보는 법」을 붙였다.

## 3. 데모 데이터 — «나빠지다 2020년에 돌아서는» 9회차

### 3-1. 최종 곡선

```
연도      2008 2010 2012 2014 2016 2018 2020 2022 2024
참고점수    94   88   82   64   52   40  *22*  34   40
대사증후군  0/5  0/5  0/5  1/5  3/5  4/5  5/5  5/5  4/5
조합         0    0    0    0    1    4    7    4    4
ASCVD      2.9  3.8  4.8  6.6  9.0 11.0 15.9 15.3 15.7%
eGFR     114.7                          85.4 G2 →  89.4 G2
```

만 40세부터 국가 일반검진 대상이라 2008년이 첫 회차다. **앞 회차를 100점으로 두지
않은 것은 일부러다** — 40세에 감점이 하나도 없는 검진표는 드물다. 점수는 주의 −6 ·
위험 −12 단위로만 움직이므로 «아주 조금씩»의 최소 단위가 6점이다.

### 3-2. 회복 곡선을 지어내지 않았다

근거문서([생활습관 효과크기](../evidence/2026-07-30-생활습관-효과크기-근거.md))에 맞춰
항목마다 반응 속도를 달리했다.

| 항목 | 변화 | 근거 |
|---|---|---|
| 감마-GTP | 82 → 64 | 절주에 가장 빨리 반응(반감기 26일) |
| ALT | 47 → 33 | 식이+운동 병행 −13.27, 등급 A |
| **LDL** | **153 → 145** | **§6-9 "체중 감량은 LDL을 움직이지 않는다"** |
| 크레아티닌 | 1.05 → 0.99 | 신장은 회복이 느리다 |

LDL을 함께 떨어뜨리면 「다음 검진 목표」가 화면에서 *"체중을 줄여도 LDL은 안 움직입니다"*
라고 말하는 **바로 그 순간 데모가 자기모순**이 된다.

ASCVD는 회복 구간에서도 15%대에 머문다. 수치는 좋아졌지만 나이가 네 살 늘어 그만큼을
상쇄했기 때문이다. **억지로 낮추지 않았다** — 나이는 되돌릴 수 없다는 사실을 화면이
그대로 말하는 편이 맞다.

### 3-3. 손댔다가 되돌린 것 둘 — 이번 작업에서 가장 값진 부분

**① 2024를 «더» 좋게 만들면 기능 하나가 사라진다.**
혈압 131·혈당 103까지 내렸더니 대사증후군 이탈도가 0.05로 떨어져
「다음 검진 목표」에서 체중·유산소·절주가 **완전 동점**이 되고 금연이 0%로 사라졌다.
어떤 행동이든 한 번에 전부 기준 아래로 내려버리기 때문이다.
**효과크기 우선순위(A-2 작업)가 데모에서 안 보이게 된다.**
지금 이탈도는 0.28이고 유산소 0.257 > 체중 0.250 > 절주 0.139 > 금연 0.091로 갈린다.

**② 바닥 해의 AST/ALT를 비슷하게 두면 지방간 판정이 통째로 사라진다.**
37/38로 뒀더니 `HSI = 8×(ALT/AST) + BMI`가 36을 못 넘어
**「지방간 유형」 카드가 아홉 해 어디에도 안 떴다.** 앱 기능 하나가 데모에서 없어진
것이다. 지방간에서 ALT 우세는 전형이므로 34/47로 바로잡았다.

> **교훈** — 데모 데이터를 «좋게» 만들면 앱의 기능이 조용히 사라진다.
> 수치를 바꾼 뒤에는 반드시 **화면에서 무엇이 없어졌는지**를 확인해야 한다.

### 3-4. 재생성 경로

```
uv run python ../tools/gen_demo_analysis.py      → tools/dummy_by_year.json
uv run python ../tools/gen_dummy_analysis_ts.py  → src/dummyAnalysis.ts
```

**`gen_dummy_analysis_ts.py`를 이번에 새로 만들었다.** `dummyAnalysis.ts`가 8천 줄이라
손으로 옮겨 적을 수 없다. 다만 파일 전체가 생성물인 것도 아니라서 «앵커 사이»만 바꾼다 —
머리말·`dummyHighlights`·`dummyInsight`·`simulateDemo`는 사람이 쓰는 자리다.

`dummyHighlights`/`dummyInsight`를 계속 사람이 쓰는 이유: 백엔드 시계열은
**첫 회차와 마지막 회차만** 비교해서 2020년 이후의 반등을 담지 못하고, 문구도
"HDL콜레스테롤은(는) 14년간 변화 폭이 같은 연령대 평균(+1.5)보다 큽니다"처럼 읽기 어렵다.

## 4. 홈 탭만 데이터가 안 따라오고 있었다

수치를 바꾼 뒤 사용자가 "모든 탭에 적용 안 된 것 같다"고 했다. 확인해 보니 **홈 탭
하나만** 그랬다.

`metricDefinitions`의 항목별 `status`가 «최신 회차 판정»으로 손으로 적혀 있었다.
검사항목·히스토리·분석은 `metricsForReport()`로 그 해 `statusByKey`를 덮어쓰지만,
**홈 탭만 이 값을 그대로 쓴다.** 그래서 허리둘레가 96 → 88로 기준 안에 들어왔는데도
홈 TOP3는 계속 「허리둘레 위험」을 가리켰다.

→ `METRIC_DEFS`에는 자리만 두고 `status`는 `latest.statusByKey`에서 **파생**시킨다.
테스트로 못 박았고, RED에서 실제로 걸렸다:

```
AssertionError: expected [ 'waist', '위험' ] to deeply equal [ 'waist', '정상' ]
```

> **교훈** — 같은 사실이 두 곳에 적혀 있으면 언젠가 갈린다. 그리고 **한 화면에서만**
> 갈리면 다른 화면이 멀쩡해서 아무도 눈치채지 못한다.

## 5. 히스토리 탭 정리

### 5-1. 카드 여덟 장이 평평했다

성격이 둘로 갈리는데 화면에 구분이 없었다. 아래 다섯에만 배지가 붙는 것도
«판정 대상이 아니라서»인데, 구획이 없으면 "배지 없는 카드는 정상인가?"로 읽힌다.
분석 탭에는 층 머리말이 있는데 히스토리만 없었다.

→ `SectionHeader` 신설: **「항목별로 보면」**(그래프) / **「여러 해를 종합하면」**(글).
분석 탭 `LayerHeader`와 같은 문법을 써서 새로 배울 몸짓을 만들지 않았다.

### 5-2. 그래프를 위로

사용자: *"첫 화면 스크롤 없이도 밑에 1뎁스 그래프들이 보이는 게 좋은 듯"*

순서를 바꿨다 — 그래프끼리(점수 추이 → 항목별 추이) 붙고, 글 위주인 종합 카드가 뒤로.
**스크롤 없이 그래프 3개**(점수 추이 · 혈압 · 혈당·체중)가 들어온다.

### 5-3. 「한눈에 요약」을 합쳤다

같은 모양의 카드 셋이 연달아 있어 무엇이 다른지 알 수 없었다. 1뎁스가
"우려 3건 · 다음 검진 2026년"뿐인데 우려는 아래 카드가 자세히 말하고, 자연어 전문은
분석 탭 ④층과 겹쳤다. **버린 것은 없다** — 전부 병합 카드 안에 있다(스펙 §1-1②).

### 5-4. 연도 칩을 넣었다가 뺐다

회차가 8개일 때는 한 줄이었는데 9개가 되면서 **두 줄을 차지해 정작 보러 온 그래프를
아래로 밀어냈다.** 연도는 그래프를 눌러 고르면 되고, 고른 해는 점선 세로선 · 값 라벨 ·
「N년 검진 수치」 제목 셋이 이미 말한다.

⚠️ 칩을 빼면 «그 해에 안 잰» 경우 그래프가 사라져 연도를 바꿀 손잡이도 없어진다.
그 자리에 「2024년으로 돌아가기」 버튼을 뒀다.

### 5-5. 「또래 대비 변화 속도」가 하던 거짓말

> "5개 항목이 또래 평균보다 빠르게 **나빠지고 있어요**"

`change_pace`는 첫 회차와 마지막 회차만 빼서 만드는 값이라 2020년 이후의 반등이
담기지 않는다. 2008년보다 2024년이 나쁜 건 사실이지만 «~고 있어요»는 현재진행형이라,
바로 위 히어로의 "2020년 이후로는 18점 올랐어요"와 **한 화면에서 정면으로 충돌**했다.

문구에서 시제를 뺐다 → "16년을 통틀어 5개 항목이 또래보다 크게 변했어요".
항목별 문구("악화 중입니다")는 백엔드가 만든 문장이라 고쳐 쓰지 않고,
2뎁스에 무엇을 비교한 값인지 한 줄을 더했다.

**카드 이름도 바꿨다** — 「또래 대비 변화 속도」 → **「또래보다 빠르게 변한 항목」**.
분석 ③층 「같은 또래는 어떤가」와 하는 일이 겹친다는 지적이 있었고, 맞는 지적이다.
옮기지 않은 이유는 분석 탭이 «한 해» 기준으로 아래 전부를 계산하기 때문이다
("여기부터 아래 모든 카드는 2024년 수치") — 변화 «속도»는 여러 해가 필요해서
그 규칙에 예외를 만들게 된다. 이름으로 가른다: **분포(위치)** vs **변화 폭**.

## 6. 곁들여 고친 것

### 6-1. 점수 추이 문장이 반등을 말한다

그래프는 V자인데 문장은 "54점 내려갔어요"만 말해 한 카드 안에서 그림과 글이 달랐다.

```
16년간 54점 내려갔지만, 2020년 이후로는 18점 올랐어요.
```

TDD로 했다(RED 확인 → GREEN). 1점 흔들림은 추세로 안 센다(`REBOUND_MIN`).

### 6-2. 음주 입력 — 계산은 맞았고 근거만 없었다

사용자: *"술 와인이 소주 맥주보다 높은데 이게 맞아?"*

**맞다.** 순알코올 g = 용량 × 도수 × 0.789로 검산하면 와인 150ml×12% = 14.2g,
소주 50ml×17% = 6.7g. 소주가 세게 느껴지는 건 도수 때문인데 **잔이 3배 작다.**

다만 칩에 `소주`·`와인`이라고만 적혀 있어 같은 "3잔"인데 g이 두 배가 되는 이유를
알 수 없었다. **잔 크기를 칩에 붙였다**(`소주 50ml` · `와인 150ml` …).

## 7. 이번에 배운 것

1. **재현 경로는 코드로 좁혀도 «어느 화면인지»는 사용자만 안다.** 히스토리/검사항목을
   되짚느라 왕복했다. 코드로 후보를 좁힌 다음, 고르게 했어야 했다.
2. **데이터를 보기 전에 제안하지 않는다.** 요약문 후보 #2(항목 이름 대기)는 실제
   항목명이 전문용어라 못 쓰는 안이었다. 값을 먼저 열어봤으면 안 냈을 제안이다.
3. **데모를 «좋게» 만들면 기능이 조용히 사라진다.** 이탈도 0.05 → 우선순위 동점,
   AST≈ALT → 지방간 판정 실종. 둘 다 화면을 보고서야 알았다.
4. **같은 사실이 두 곳에 적혀 있으면 갈린다.** `metricDefinitions.status`가 홈 탭
   하나에서만 옛 판정을 가리키고 있었고, 다른 세 탭이 멀쩡해서 안 보였다.
5. **레이아웃은 네 번 고쳐야 할 수도 있다.** 한 번에 맞히려 하지 말고 화면을 보고
   고치는 게 빠르다. 다만 **왜 이전 안이 틀렸는지**는 남겨야 같은 자리를 또 돌지 않는다.
