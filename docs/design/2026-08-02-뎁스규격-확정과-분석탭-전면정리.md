## 1. 왜 시작했나

사용자가 「1뎁스 2뎁스 2.5뎁스에 대하여 이야기해보자」로 열었다. 확인해 보니
**뎁스라는 말이 앱 안에서 세 가지 뜻으로 쓰이고 있었다.**

| 출처 | 표기 | 세는 것 |
|---|---|---|
| 스펙 §2 | L0 · L1 · L2 · L3 | 화면 깊이 |
| 코드 주석 | 1뎁스 · 2뎁스 · 2.5뎁스 | 같은 것, 다른 이름 |
| 분석 탭 | ①②③④층 | **깊이가 아니라 가로 구획** |

한 화면에서 원문자 ①이 세 가지를 가리키고 있었다(①층 · 모달 안 ①결론 · 홈 TOP3 ①번).

## 2. 규격 — 스펙 §2-1 신설

§2는 «어느 층에 두나»만 정했고 «각 층이 어떻게 생겼나»는 정하지 않았다. 다섯 축으로 채웠다.

### 축 0 — 각 층이 답하는 질문 (배치의 1차 기준)

| 층 | 질문 | 다음 행동 |
|---|---|---|
| 1뎁스 | 내가 이걸 봐야 하나? | 연다 / 안 연다 |
| 2뎁스 | 뭔데 · 나는 어떤데 · 뭘 하면 되는데 | 행동을 정한다 |
| 2.5뎁스 | 왜 그렇게 판정했는데? | 믿는다 / 안 믿는다 |

**판별 테스트** — 지웠을 때 *열지 말지*가 흔들리면 1뎁스, *믿을지*가 흔들리면 2.5뎁스.

### 축 1 — 중요도 × 어려움

|  | 쉽다 | 어렵다 |
|---|---|---|
| **중요** | 1뎁스 그대로 | **1뎁스엔 번역한 결론만, 원문은 2.5뎁스** |
| **부차** | 2뎁스 ②·③ | 2.5뎁스 |

### 축 2 — 언어: 「종이에 있나」

- 「감마-GTP」·「크레아티닌」 → 결과지에 인쇄됨 → **1뎁스 허용**(뜻풀이 필수)
- 「지방간 보조지표」·「간 계산기」 → **우리가 지은 이름** → 번역 대상

### 축 3 — 분량

| 층 | 상한 |
|---|---|
| 1뎁스 | 제목 배지 있으면 12자·없으면 15자 · 결론 1문장 40자 |
| 2뎁스 | 칸당 1~3문장 · **본문은 스크롤 없이 읽히는 분량까지** |
| 2.5뎁스 | 접힌 채 시작 · 펼쳐서 6줄 넘으면 3뎁스 검토 신호 |

### 축 4 — 순서

- 1뎁스: 탭마다 정렬 기준 하나, **화면이 그 기준을 말한다**
  (⚠️ 판단 요소끼리의 순서다. 도구 카드는 대상이 아니다 — 홈 「빠른 이동」 참조)
- 2뎁스: ①결론 → ②정의 → ③위치 → ④의미 → ⑤행동, 예외 없음

### ③「나의 위치」 — 비교축 (코드가 강제)

> 위치는 언제나 «무엇에 대한» 위치다.

`standard`(기준) · `peer`(또래) · `time`(과거의 나) 셋뿐. 제목은 축에서 파생하고,
축이 없으면 ③칸을 아예 그리지 않는다. `axes`는 **선택이 아니라 필수**라 새 카드가
축을 빠뜨리면 컴파일이 막힌다.

### ④「그래서 이게 의미하는 건」 — 오해 차단

`meaning` 18개를 전수로 읽어 분류한 결과 하는 일이 둘뿐이었다:
**오해 차단**("유지된다고 가정한 수치") + 역할 설명. §7「진단 단정 금지」가 실제로
지켜지는 자리라 없애지 않는다.

### 2뎁스는 요약이다 — 원문은 접는다

「칸당 1~3문장」이 `definition`·`meaning` 같은 **문장 필드에만** 걸려 있었고,
정작 부피를 만드는 본문(`children`·`tipsExtra`)에는 상한이 없었다. 그래서 층이
실질적으로 둘이었다 — 1뎁스=결론, **2뎁스=전부**, 2.5뎁스=②의 심화만.

→ `Expandable` 도입. 접기 전에 **안에 무엇이 얼마나 있는지 한 줄로 알린다.**
접는 버튼은 ②의 「자세히 알아보기」와 **같은 모양**을 쓴다.

## 3. 분석 탭 — 무엇을 바꿨나

### ①층: 히어로 + 카드 하나

```
① 기준을 벗어났나
[2024년][2022년][2020년] …          ← 연도 칩을 카드 밖으로

참고 점수 40 / 100점  [주의가 필요해요]
점수만 보고 넘기면 놓치는 신호가 4가지 있어요.
      신호 4가지 보기 ⌄              ← 「어떻게 계산했나요?」도 이 안에

나는 어떤 상태인가  [주의가 필요해요] ›
위험 1 · 주의 8 · 상태 기준 7개 해당
```

- 「집단군 판정」 → **「나는 어떤 상태인가」** (사용자 명명)
- 2뎁스 ③이 **「항목으로 보면」 / 「상태로 보면」** 둘로 나뉜다.
  항목은 개수가 아니라 **BMI 25.2 위험 · 수축기 혈압 134 주의**처럼 이름과 값을 적는다 —
  히어로가 40점만 말하고 «무엇이» 나쁜지는 앱 어디에도 답이 없었다.
- 목록은 위험→주의 순 **4개 + 「나머지 N개 보기」**

### ②층: 카드 이름을 질문형으로

| 전 | 후 | 용어 라벨 |
|---|---|---|
| 신장 기능 (eGFR) | 콩팥이 잘 거르고 있나 | `eGFR` |
| 지방간 보조지표 + 지방간 유형 | **간에 지방이 꼈나** (합침) | `FLI·HSI` |
| 간 계산기 | 간이 굳어가고 있나 | `BARD·De Ritis` |
| 대사·지질 계산기 | 혈당·지질에 이상이 있나 | `TyG·Non-HDL` |
| LDL 콜레스테롤 개인 목표 | 내 LDL 목표를 넘었나 | — |
| 심혈관 위험 참고 시뮬레이션 | 심혈관 위험이 얼마나 되나 | `ASCVD` |

제목은 쉬운 질문, **용어는 제목 옆 작은 회색 라벨**(`term`), 결론은 답.
검사항목 탭의 «항목명 + 작은 뜻풀이»와 같은 모양이고 방향만 반대다.

### ③층

| 전 | 후 |
|---|---|
| 같은 또래 분포 | 나 같은 사람이 얼마나 되나 |
| 함께 나타나는 조합 (동반 경향) | 이 조합이 흔한가 |
| 같은 나이대의 16년 변화 | 또래 자체가 나빠졌나 |

### 결론은 개수가 아니라 «판정»

「간에 지방이 꼈나」에 「지표 2개 중 2개가 기준 밖」은 답이 아니다 —
계산 도구 이야기지 간 이야기가 아니고, 판단은 배지가 이미 말한다.
백엔드가 지표마다 보내주는 `interpretation`이 실제 답이었다.

| 카드 | 결론 |
|---|---|
| 간에 지방이 꼈나 | 2개 지표 모두 **판단 보류 구간 (중간)**이에요 |
| 간이 굳어가고 있나 | **진행 간섬유화 배제 불가 (추가 평가 권장)** |

두 번째는 「추가 평가 권장」이라는 **행동**까지 준다.

⚠️ 「혈당·지질에 이상이 있나」만 개수를 유지한다 — 지표가 7종이라 하나만 꺼내면
나머지가 묻히고, 이름(TyG·Non-HDL·MAP)이 전부 전문용어라 1뎁스에 못 쓴다.

### 카드 7장을 접었다

맞춤 권장사항 ⑤ · 나는 어떤 상태인가 ③ · 나 같은 사람이 얼마나 되나 ③ ·
이 조합이 흔한가 ③ · 또래 자체가 나빠졌나 ④ · 주목할 만한 변화 ③ ·
또래보다 빠르게 변한 항목 ③

결과: **「맞춤 권장사항」이 세 화면 → 한 화면**, 심혈관·eGFR·LDL도 스크롤 없이 다 들어온다.

## 4. 전수 감사에서 나온 것

### ③ 첫 줄이 ②를 그대로 반복 — 7장

카드를 하나씩 열다 패턴을 발견해 코드로 전수 확인했다. ③이 카드의 «본문»이던 시절의
도입문이 ②가 생긴 뒤로 중복이 된 것이다. **심혈관은 ③이 더 어려운 말을 써서 축 2를
역행**하고 있었다:

- ② "10년 안에 **심근경색·뇌졸중**이 생길 확률"
- ③ "10년 내 **죽상경화성 심혈관질환(ASCVD)** 위험"

### 공식이 2뎁스에 노출 — 계산기 2장

`De Ritis = AST / ALT` · `BARD = BMI≥28(1) + … [Harrison 2008]` ·
`Non-HDL-C = 총콜레스테롤 − HDL (NCEP ATP III)` → 2.5뎁스로 접었다.
**컷오프는 값의 «눈금»이라 ③에 남겼다** — 없으면 숫자를 읽을 수 없다.

### 「이 지표는요」 18개 → 4건 교정

| 카드 | 문제 |
|---|---|
| 간 기능 | 「간담도계」 → 「담즙이 지나는 길」 |
| eGFR | **용어가 먼저** → 「피 속 노폐물(크레아티닌) 수치로 가늠한…」 |
| 간 계산기 | 「섬유화」 → 「간이 굳어가는 정도(섬유화)」 |
| 맞춤 권장사항 | 「판정된 집단군」 → 「해당하는 상태 기준」 (개명 잔재) |

나머지 14개는 이미 «쉬운 말 먼저, 괄호로 원어»를 지키고 있었다.

### UI/UX 4원칙

| 원칙 | 결과 |
|---|---|
| 1 직관성 | 접기·배지·chevron 문법이 앱 전체에서 하나로 수렴 |
| 2 일관성 | **위반 발견 → 수정.** 심혈관 카드 한 장 안에 접기가 두 모양이었다 |
| 3 가독성 | ⚠️ `fontSize ≤ 11`이 **77곳**. 스펙 §7 「본문 16 미만 금지」와 충돌 — 미해결 |
| 3 접근성 | ⚠️ `hitSlop` 없는 `Pressable` 22곳 — 미해결 |
| 4 반응성 | UploadScreen 22곳 충실. 나머지 탭은 로컬 데이터라 해당 없음 |

## 5. 틀렸던 것 — 정정 기록

이 작업에서 내가 틀리고 고친 것들이다. 같은 실수를 반복하지 않으려고 남긴다.

| # | 주장 | 실제 |
|---|---|---|
| 1 | 「카드 2.5뎁스 18/33, 15장이 빔」 | `cardContent`는 18키 전부 쓰이고 `detail`은 17/18. 33은 `METRIC_LABEL` 15개가 섞인 수 |
| 2 | 「2.5뎁스 전부 6줄 미만」 | **재보지 않고 적었다.** 실측 34개 중 5개 초과(최대 8줄) |

| 4 | 「2024년 지방간 유형이 HSI 35라서 안 뜬다」 | 게이트는 HSI가 아니라 **「지방간 의심」(ALT>40 또는 GGT>75)**. 데모에서는 2020년에만 뜬다 |
| 5 | 「`sbp.detail`이 ②와 ④를 겸한다」 | 확정한 규격이 측정 조건·한계를 2.5뎁스에 넣기로 했으므로 **위반이 아니다** |

### 되돌린 것 4건

| 되돌림 | 이유 |
|---|---|
| 홈 「빠른 이동」을 TOP 3 아래로 → **중간으로 복귀** | 축 4의 «심각도 순»은 판단 요소끼리의 순서지 도구 카드까지 밀라는 뜻이 아니다 |
| 두 카드를 한 장으로 합침 → **두 장으로 복귀** | 요청을 잘못 읽었다. 「히어로 + 아래 카드」가 원래 뜻이었다 |
| 「신호 4가지」를 아래 카드로 → **히어로로 복귀** | 「이 점수에」로 시작하는 말이라 점수 옆에 있어야 한다 |
| 장기 구획 삭제 → **원래 모양으로 복귀** | 지우기·11pt 회색·가운데 정렬을 다 해보고 원래(왼쪽·15pt·볼드)가 제일 나았다 |

**마지막 것이 가장 큰 교훈이다.** 「신장 / 콩팥이 잘 거르고 있나」를 «같은 말 두 번»으로
보고 지웠는데, 실제 화면에서는 **머리말이 구획을, 카드가 질문을 말해서 읽는 층위가
다르다.** 코드만 보고 내린 판단이었다.

## 6. tsc가 못 잡는 오류 — 반드시 기억할 것

**`cardContent` 키는 문자열이라 타입 검사에 안 걸린다.** 카드 이름을 바꾸면서
`cardContent['지방간']` 참조 4곳을 놓쳤는데, tsc도 테스트도 통과하고 화면에서
②·④·⑤가 **조용히 빈 칸**이 됐다.

```bash
# 카드 이름을 바꾼 뒤에는 반드시 이 대조를 돌릴 것
node -e "
const fs=require('fs');
const d=fs.readFileSync('data.ts','utf8');
const cc=d.indexOf('export const cardContent'), end=d.indexOf('\n};', cc);
const keys=new Set([...d.slice(cc,end).matchAll(/^  '([^']+)':/gm)].map(m=>m[1]));
const src=['screens/AnalysisScreen.tsx','screens/HistoryScreen.tsx']
  .map(f=>fs.readFileSync(f,'utf8')).join('\n');
const used=[...new Set([...src.matchAll(/cardContent\['([^']+)'\]/g)].map(m=>m[1]))];
const missing=used.filter(k=>!keys.has(k));
console.log(missing.length ? '❌ '+missing.join(' / ') : '✅ 참조 전부 존재');
"
```

**JSX 연산자 우선순위**도 같은 종류다. `{A || B && <X/>}`는 `{A || (B && <X/>)}`로
묶여서, A가 참이면 식이 `true`가 되고 React는 `true`를 아무것도 그리지 않는다.
「심혈관」 구획이 이 때문에 조용히 사라졌다. **괄호를 반드시 칠 것.**

그리고 **JSX 속성 자리에 `{/* */}` 주석을 넣으면 `TS1005`**다. 이 작업에서만 네 번 냈다.
주석은 요소 «위»에 둘 것.
