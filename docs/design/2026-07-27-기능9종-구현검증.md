## 2. 그룹별 상세

### G1 · 분석엔진 (`a49e538`)

| 항목 | 무엇을 했나 | 실화면 검증 |
|---|---|---|
| **② TG≥400 LDL 가드** | `clinical_targets.classify_ldl_risk`에 Friedewald 가드. TG≥400이면 `achieved=None`으로 **판정 보류**하고 `ldl_reliable`·`reliability_note` 내림 | TG 178 → "목표 초과 +15" 유지 / TG 450 → **"판정 보류" 배지 + 경고박스** |
| **③ ALT/GGT 비** | `calculators.py`에 함수 추가. 유형 감별이라 `level:'info'`(중립 회색) | **0.66** "알코올성 쪽 시사". 계산기 14→**15종** |
| **⑤ 또래 변화속도** | `analyze_change_pace()` + `change_pace` 상위 5종. 파이프라인 재투영에도 추가 | 수축기 **19.0배** · 이완기 13.7 · 공복혈당 11.7 · 중성지방 9.2 · Non-HDL 7.3 |

**설계 판단 2개**
- ②는 기능 추가가 아니라 **정합성 수정**에 가깝다. 23번에서 노출한 LDL 목표 카드가
  TG 높은 사용자에게 *자신 있게 틀린* 달성 판정을 보여주고 있었다(교수 주석 p9).
- ⑤의 배수는 또래 평균 변화가 ±0.5 미만이면 발산한다(0.05 대비 5.0 = 100배).
  그때는 배수를 내지 않고 **"또래는 거의 그대로인데 본인만 +5"** 로 서술한다.
  화면에도 "배수는 **평균과의 비교**라서 또래 안의 개인차는 담기지 않는다"를 명시.

### G2 · 입력경로 (`9db522e`)

| 항목 | 무엇을 했나 | 실화면 검증 |
|---|---|---|
| **⑥ 직접 입력** | 빈 `ocr` 골격을 만들어 **기존 저장 경로를 그대로 재사용**(분석·저장 코드 신규 0줄) | 빈 폼 정상. 저장 시도 전엔 "확인 필요" 배너 억제 |
| **⑦ 검수 하이라이트** | `measurements_confidence` 연결 + `flags` → 사람말 변환. 0.7 미만 표시 | 이완기 **확신 50%**+"범위를 벗어난 값" / 공복혈당 **62%**+"판독이 불확실" · **편집 시 즉시 해제** |
| **① 음주량** | **신규 코드 없음 — 이미 구현돼 있었다** | 100g→MASLD / 300g→MetALD / **500g→ALD** (`provisional:false`) |

**정정 기록 (중요)**
계획 단계에서 ①을 "백엔드는 완성, 입구만 없음"으로 판단했는데 **틀렸다.**
`LifestyleForm`(주횟수×잔수×술종류→순알코올 g) → `ocr_adapter`의
`alcohol_weekly_g → "주당순알코올(g)"` 매핑 → `combo_group_analysis` 3구간이
**전부 연결돼 있었다.** 근거로 삼은 코드 문구는 값이 *없을 때의 폴백 안내*였다.
→ **교훈: 코드 주석이 아니라 호출 경로를 따라가서 확인해야 한다.**

**대신 찾은 진짜 갭**
`ocrTemplate`에 **하드코딩된 허구 confidence 18개**(hospital 0.42 등)가 있었고,
백엔드가 내려주는 **실제 `measurements_confidence`는 버려지고 있었다.**
아무도 읽지 않아 드러나지 않았는데 ⑦로 화면에 띄우게 되므로 허구값을 제거하고
실제 값만 쓰게 했다(`OcrField.confidence`를 optional로).

### G3 · What-if 시뮬레이터 (`3c178e2`) ★ 발표 킬러

- **백엔드**: `_internal/what_if.py` 신규 + `POST /analyze/simulate`.
  최근 저장 검진값을 기준선으로 써서 **화면 값과 계산 기준이 항상 일치**. 저장 안 함.
- **앱**: `components/WhatIfSimulator.tsx` — 스테퍼 7종
  (허리·수축기·이완기·공복혈당·중성지방·HDL·LDL).

**실계정 실화면**: 허리 −5 · 혈당 −14 · 중성지방 −35 · HDL +6 →
- **대사증후군 5 → 1** + "3개 미만이 되어 대사증후군 기준에서 벗어나요"
- METS-IR **또래 상위 77.3% → 65.4%** · LAP 76%→56.5% · VAI 76.7%→56.1%
- "그대로인 지표 4종 — 바꾼 값이 이 지표의 계산식에 들어가지 않아서예요"

**핵심 원칙 — 예측하지 않는다**
> 답하지 않는 질문: "5kg 빼면 중성지방이 얼마나 내려가나" (개인차가 커서 추정 불가)
> 답하는 질문: "다음 검진에 이 값이 나오면 대사증후군에서 벗어나나" (결정론적 공식)

이 구분을 응답 `limitations`에 명시했다. 발표 때 **가장 강하게 말할 수 있는 부분**.

**정직성 사례**: 체중만 줄이면 **VAI는 오히려 2.64→2.76으로 나빠진다**
(VAI 식의 분모에 BMI가 있어서). 지표가 서로 다른 방향으로 움직일 수 있음을
감추지 않고 그대로 보여준다.

## 3. 🐛 선행 버그 3건 — 이번 작업 최대 수확

**전부 root 더미가 가려놓고 있던 실계정 전용 버그.**
공통 원인: **더미는 프론트 자체 키를, 실데이터는 백엔드 형식을 쓰는데 그 사이 변환이 빠져 있었음.**

| # | 버그 | 실제 증상 | 발견 계기 | 고친 곳 |
|---|---|---|---|---|
| 1 | `fetchTimeseries` 언랩 누락 | `GET /timeseries/{id}`는 DB 행(`{timeseries_data, insights}`)을 그대로 주는데 언랩이 없어 **23번에서 넣은 insight·highlights가 실계정에서 전부 `undefined`** | ⑤ 구현 중 | `health.ts` |
| 2 | `METRIC_NAME_TO_KEY` 명칭 누락 | 백엔드 실제 명칭(`식전혈당(공복혈당)`·`트리글리세라이드`·`혈청지오티(AST)`·`혈청지피티(ALT)`)이 맵에 없어 **4개 지표가 실계정 화면에 아예 없었음** | ④ 스테퍼가 7개 중 5개만 떠서 | `health.ts` |
| 3 | 데모 로그인 프로필 미초기화 | root 데모가 직전 실계정의 이름·성별·생년을 물려받아 **내보낸 PDF에 남의 이름이 찍힘** | ⑨ PDF 머리말에 "웹데모" | `App.tsx` |

> ### ⚠️ 교훈 — "더미로 검증했더니 통과했다"는 위험신호다
> 3건 모두 **기능을 새로 만들다가 부수적으로** 드러났다. 의도해서 찾은 게 아니다.
> 23번 작업에서 insight를 넣고 "에뮬레이터로 검증 완료"했지만, 그 검증은
> **root 더미(하드코딩)** 로 한 것이어서 실계정 경로의 결함을 통과시켰다.
> **→ 신규 기능은 반드시 실계정 경로로 한 번 더 확인한다.**

기타 수정 3건
- HDL 증가가 개선인데 경고색으로 보이던 문제(`higherBetter` 플래그).
- 시뮬레이터 기준선이 연도 선택과 어긋나던 문제(서버는 항상 최신 기준).
- 시계열 지표명이 백엔드 내부 키(`non_HDL` 등)로 노출되던 문제(`METRIC_LABEL` 맵).

## 4. 검증 방법 (매 그룹 공통)

1. **백엔드 런타임 직접 호출** — 경계값·결측·반대방향 케이스
   (TG 178/450, ALT/GGT 결측, 또래 무변화, 음주량 4구간)
2. **`tsc --noEmit` 0 에러** / **`pytest`**
3. **에뮬레이터 실화면 스크린샷** (사용자 요구사항: 검증은 에뮬레이터로)
4. 양성 케이스가 자연 발생하지 않으면 **임시 주입 → 확인 → 원복**
   (TG 450 ldl_target, 백엔드 형태 confidence payload)
5. `dummyAnalysis.ts`는 **실제 `analyze()` 산출을 임베드**해 재생성.
   `change_pace` 더미도 6개년을 `analyze_timeseries`에 넣은 실제 값(공단 표본 조회).

**남은 red 1건 (기존 문제)**
`test_analyzer_isolation` — `calculators.py`의 `from app.renal.gfr import`가
`_internal` 격리 규칙 위반. **HEAD로 되돌려도 동일하게 실패**한다(65\~66 passed / 1 failed).
eGFR을 인자로 넘기면 풀린다. 이번 작업에서 손대지 않았다.
