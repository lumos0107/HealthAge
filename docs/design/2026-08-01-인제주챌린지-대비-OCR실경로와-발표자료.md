`WITHUS/input/인제주첼린지 운영 방침/` PDF 3종을 읽고 배점표를 확인했다.

| 평가영역 | 배점 | 자체 추정 | 근거 |
|---|---|---|---|
| 문제 정의 및 기획력 | 20 | 15~16 | 정의는 탄탄. **'현장·기업 수요'와 어긋남**(우리는 B2C) |

## 2. 실경로 검증 — 판넬 주장을 실제로 돌려봤다

### 2-1. OCR 16/16이 «실제 공단 결과통보서»에서 재현됐다

`WITHUS/테스트검진지_마스킹/`의 마스킹 실결과지(원본 PDF에서 개인정보만 치환)를
**진짜 OCR 파이프라인**에 넣었다.

```
extraction_rate 1.0 · confidence 0.89 · measurements 16/16
meta  (검진일 가림) · 1970-01-01 · M · 홍길동 · 한국건강관리협회건강증진의원
lifestyle  흡연 current · 음주 no
```

지금까지의 "16/16"은 합성 결과지 기준이었다. **실제 공단 양식에서 재현된 것은 이번이 처음**이고,
발표 p12에 그대로 쓸 수 있다.

### 2-2. 환각 방지의 «실체»가 로그로 잡힌다

발표 원고엔 "환각 0"이라는 결과만 있고 **어떻게 막았는지**가 없었다. 실제 로그:

```
[TablePipeline] 영역 게이트: 측정값 표 없음 판정 — 수치 추출 생략 (환각 방지)
[TablePipeline] 게이트 판정에 따라 수치 1개 폐기 (환각 의심)
[TablePipeline] 혈색소 재시도 값 13.5에 전사 근거 없음 — 폐기
```

**모델을 믿는 게 아니라 근거 없는 값을 버린다.** 이게 25점짜리 항목의 재료다.

### 2-3. 하이브리드 전처리는 이미 하고 있었다

"OpenCV 전처리 → Gemini OCR"이 권장이라는데, 이미 그 구조다
(`splitter/components/opencv_table_detector.py` · `hybrid_splitter.py`).
Otsu 이진화 → 가로/세로선 opening → 격자 검출 → 영역별 분기 → 비전 모델.
**인용문에 없는 게이트·전사 교차검증까지 있다.** 다른 건 마지막 단계의 모델뿐이다.

## 3. 발견해서 고친 것 셋 — 전부 «주장이 사실이 아니었던» 것

### 3-1. 마스킹에 실존 의사의 이름·면허번호가 남아 있었다 — `a061d87`

부스에 띄울 자료인데 결과통보서 마지막 장에 **검진의사 실명(가림)·면허번호(가림)·
요양기관기호(가림)** 가 그대로 있었다. 기존 스크립트는 **수검자만** 치환한다.

**두 번 실패한 뒤에야 원인을 알았다.** 라벨(«검진의사» «면허(자격)번호» «성명» «요양기관기호»)이
전부 **텍스트가 아니라 양식 그림**이라 `page.search_for()`가 0 hit이다. 텍스트로 있는 건 값뿐.

→ 값을 직접 잡는다: ① 5자리 이상 숫자 중 날짜 아닌 것 → `0`으로 ② 그 숫자와 **같은 y 띠**의
한글 2~4자 → 가짜 의사명. y 띠로 좁힌 이유는 페이지 전체에서 한글 2~4자를 지우면
'기타질환'·'내원' 같은 양식 값까지 날아가기 때문이다. 병원명(13자)은 길이에서 걸러진다.

> **교훈**: PDF를 열어보기 전에 두 번 고쳤고 두 번 다 틀렸다. 인수인계 §7-2가 적어둔
> "코드·데이터를 열어보고 나서 말할 것"이 또 맞았다.

### 3-2. Gemini 백엔드는 한 번도 돌아본 적이 없었다 — `495702b`

판넬에 "OCR 비전 AI (Ollama / **Gemini**)"라고 인쇄돼 있다. 키를 넣자마자:

```
404 NOT_FOUND: models/qwen2.5vl:7b-q8_0 is not found
```

파이프라인 **세 곳**이 Ollama 모델명을 백엔드에 강제하고 있었다
(`table_pipeline` 396·784, `graphic_pipeline` 125). 전부 `model=None`으로 두어
각 백엔드가 자기 `default_model`을 쓰게 했다.

**그리고 무료 등급 한도가 측정으로 확인됐다:**

```
quotaId: GenerateRequestsPerMinutePerProjectPerModel-FreeTier
model: gemini-2.5-flash        quotaValue: '5'      ← 분당 5회
```

파이프라인은 3페이지에 10~15회를 부른다. **무료 등급으로는 부스 라이브 시연 불가.**

### 3-3. 기울기 보정이 없었다 — `495702b`

표 검출이 «가로선/세로선 morphological opening»이라 **문서가 기울면 격자를 통째로 못 잡는다.**
지금까지 문제가 안 된 건 테스트가 전부 PDF 렌더링본(반듯함)이었기 때문이고,
**폰으로 찍는 순간 깨진다.**

`image_utils.correct_document_orientation()` 신설 → `entry._process_checkup`에 연결.

```
 deg   method   angle    가로선(기울임 → 보정)
   0     none     0.0     12436 → 12436   (안 건드림)
  +3   rotate    -3.0         0 → 13170
  -3   rotate    +3.0         0 → 12440
  +8   rotate    -8.0      4422 → 12445
 +40     none     0.0     (기울기로 안 봄 — 과보정 방지)
```

**실증**: 6도 기울인 실제 결과지에서 **수치 16/16 전부 추출**(rate 0.89 · conf 0.88).

두 가지 판단:
- **원근(4점 투시) 보정은 뺐다.** 넣어 봤더니 반듯한 스캔본에서 «표 테두리»를 문서로 오인해
  표만 잘라냈다. "배경 위의 문서"와 "종이 안의 표"를 가리는 판단이 필요한데 잘못하면
  이미지를 통째로 망친다. 이유를 코드에 남겼다
- **`minAreaRect` 각도 범위를 한쪽만 정규화**해 −3·−5·−8도가 전부 감지 실패했다.
  OpenCV 4.5 이후는 `(-90, 0]`. 테스트 파라미터에 음수 방향을 넣어 회귀를 막는다

**알려진 한계**: 같은 기울인 입력에서 meta(생년월일·검진일)는 틀렸다. 반듯한 같은 2장은
rate 1.0에 meta도 정확해 «페이지 수»가 아니라 «기울기»가 원인인 것은 갈랐다. 다만 이 테스트는
리샘플링을 **두 번** 한다(반듯한 원본을 인위 회전 → 보정). 실제로는 기울게 찍힌 사진을
한 번만 펴므로 작은 글자 열화가 덜하다 — **실제 폰 촬영본으로 재확인이 필요하다.**

### 3-4. 부수 — `_internal` 격리 테스트가 상시 red였다 — `e5f87f8`

`calculators.py`가 `from app.renal.gfr import ...`를 해서 분석 모듈 격리 규칙을 깨고 있었다.
CKD-EPI 2021을 `_internal` 안에 순수 함수로 두고, **두 구현이 같은 값을 내는지**를
`test_egfr_parity.py`가 고정한다(κ 경계 양쪽·노인·신부전 20조합).

→ **"자동 테스트 전부 통과"가 이제 사실이다.**

## 4. 계산기 개수 — 22종이 맞다

판넬 «20종» · 앱 문구 «22종» · 백엔드 응답 «15개»로 세 곳이 달랐다.
코드로 세어 **22종**으로 확정했다. 처음에 20이라고 결론 냈던 것은 틀렸다 —
`additional_calculators` 모듈만 세고 **지방간 유형 판정과 LDL 개인 목표를 뺐다.**

| 묶음 | 개수 | 내역 |
|---|---|---|
| `renal/gfr` | 2 | eGFR · CrCl |
| `clinical_targets` | 3 | FLI · HSI · **LDL 개인 목표** |
| `combo_group_analysis` | 1 | **지방간 유형(MASLD/MetALD/ALD)** |
| `calculators` | 12 | Non-HDL · Castelli I·II · AIP · TyG · METS-IR · LAP · VAI · De Ritis · ALT/GGT · BARD · MAP |
| `risk_engines` | 3 | PREVENT · Framingham · SCORE2 |
| `ascvd` | 1 | ASCVD Pooled Cohort |
| | **22** | 전체 목록은 발표 원고 부록 A5 |

**판넬의 «20종»이 과소 표기다.** 질문이 나오면 "판넬 제작 후 그 둘까지 포함해 다시 셌다"고
답하면 된다 — 목록을 대면 세어볼 수 있어 오히려 유리하다.

## 5. 발표자료 3종 (`WITHUS/인제주_판넬/`)

| 문서 | 내용 |
|---|---|
| `02_발표자료_설계` | 목차·배점 대응·페이지별 뼈대 (18p · 12:25) |
| `03_발표자료_원고` | 페이지별 «슬라이드 글 / 비주얼 / 말할 것 / 시간 / 배점» + 부록 A5 계산기 22종 |
| `04_발표자료_페이지설계` | 1920×1080 그리드·타이포·컬러 + 페이지별 레이아웃 |

**설계 판단 넷**
1. **판넬과 같은 문장으로 시작.** 부스 투어가 발표 뒤(8/5 17:30~)라 심사위원이 두 번 본다
2. **②의 제목이 "IoT 설계 방향"이지만 IoT로 재정의하지 않는다.** 실제 요구는
   «시스템 구조 + 서비스 시나리오»고 판넬이 이미 갖고 있다. p7에서 데이터 흐름을
   `수집 → 전송 → 처리 → 피드백` 4단으로 라벨링해 골격만 같게 보이게 하고,
   **"우리는 IoT다"라고 말하지 않는다.** IoT는 p18 확장에서 회수
3. **p12가 25점의 절반을 가져간다.** 세부가 «시스템 안정성 및 **시연 가능성**»이라
   **분석 경로에 LLM 0건**이 그대로 점수가 된다
4. **⑤를 2장 → 3장으로 늘렸다.** 붙임2가 «사업화 가능성»·«창업 가능성»을 명시하는데
   비어 있었다. p17(수익모델 3갈래 중 검진기관 B2B2C 권장) · p18(규제 경계 · 3단계 데이터
   거버넌스 · 센서 확장) 신설

## 6. 부스 운영 결론

| 상황 | 대응 |
|---|---|
| 기본 | **사전 업로드분 결과 화면부터** — OCR을 필수 경로에 두지 않는다 |
| "진짜 되나요?" | 1장 라이브 (Gemini면 수십 초, 로컬이면 90초/장) |
| 네트워크·한도 문제 | 사전 업로드분으로 계속 — 시연이 안 끊긴다 |
| 폰 촬영 | **갤러리에서 파일 선택** 권장. 기울기 보정은 구현했지만 실촬영 검증 전이다 |

**5분 슬롯(질의응답 포함)에 OCR을 필수로 두면 안 된다.** Gemini를 켜도 마찬가지다.

## 7. 함정 — 이번에 겪은 것

### 7-1. 「Metro stale」의 네 번째 변종은 35번에 기록됨 (앱이 두 개)

### 7-2. 라벨이 텍스트가 아니라 그림일 수 있다

마스킹을 두 번 잘못 고쳤다. `page.search_for("검진의사")`가 0 hit인데 그걸 확인하지 않고
"라인 매칭이 안 되나 보다" → "라벨 오른쪽을 가리자"로 넘어갔다.
**PDF span을 덤프하고 나서야** 라벨이 양식 그림이고 값만 텍스트라는 걸 알았다.

### 7-3. 합성 테스트가 실제보다 가혹할 수 있다

기울기 보정 검증에서 meta가 틀렸는데, 원인이 **리샘플링 두 번**일 가능성이 크다.
실제 경로는 한 번이다. **"테스트가 실패했다"와 "기능이 실패한다"는 다르다** —
테스트 설계가 실제 경로와 다른지부터 봐야 한다.
