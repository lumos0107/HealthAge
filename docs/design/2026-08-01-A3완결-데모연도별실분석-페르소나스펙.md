## 1. APK 게이트 — 존재 이유를 스스로 증명했다

**기록에 시도 흔적이 없었다.** 정리 폴더·git log 어디에도 APK 빌드 기록이 없었고,
Expo Go APK를 에뮬레이터에 복사한 기록(23·27번)만 있었다. 직접 해 봤다.

### 1-1. 빌드 실패의 진짜 원인은 경로 길이였다

`expo prebuild`는 성공했지만 gradle 네이티브 빌드가 CMake/ninja 단계에서 실패했다.

```
ninja: error: Stat(...\node_modules\@react-native-async-storage\...\ComponentDescriptors.cpp):
       Filename longer than 260 characters
```

**미지의 작업이 아니라 Windows 260자 경로 제한이었다.** 워크트리 경로
(`...\worktrees\design-b\frontend-mobile\node_modules\...`)가 길어 한계를 넘었다.
시스템 장경로 설정도 꺼져 있었다(`LongPathsEnabled=0`).

- **정션(`C:\hma`) 우회는 실패했다** — gradle이 실제 경로로 정규화한다.
- **해결**: `C:\hab`에 실제 복사 후 빌드 → **BUILD SUCCESSFUL**, `app-release.apk` 70.6MB.

> 앞으로도 APK가 필요하면 **워크트리 → `C:\hab` 동기화 → gradlew** 흐름을 쓴다.
> 근본 해결은 관리자 권한으로 `LongPathsEnabled=1`.

### 1-2. 그리고 진짜 버그가 나왔다 (`0cae93f`)

빌드된 APK를 설치하니 **부팅 즉시 죽었다.**

```
FATAL EXCEPTION: NoSuchMethodError: getDirectConverter
  at expo.modules.font.FontLoaderModule.definition(FontLoaderModule.kt:98)
  at expo.modules.kotlin.ModuleRegistry.register → ReactInstance.<init>
```

`expo-font`가 `^56.0.5`로 잡혀 있었는데 SDK 54가 기대하는 건 `~14.0.12`였다.
버전이 어긋난 네이티브 모듈이 `expo-modules-core`의 없는 메서드를 부르며
ReactInstance 초기화에서 크래시했다.

**이건 Expo Go에서는 절대 안 드러난다.** Expo Go는 자기 바이너리에 포함된 네이티브
모듈을 쓰므로 `package.json`의 버전 불일치가 가려진다. **APK로 빌드해야만 보이는
종류의 버그**였고, 그래서 이 게이트가 필요했다.

`npx expo install expo-font`로 맞추니(app.json에 config plugin도 추가됨) 재빌드·재설치
후 분석 탭까지 정상 렌더됐다.

## 2. A3 — 관리 참고군 카드 5장 제거 (`59b8968`)

앞 문서에서 **한 작업에 네 번 뒤집혀** 보류했던 건이다. "A1'·A2'·A7이 반영된 화면을
보고 다시 판단한다"가 조건이었고, 화면을 본 뒤 **제거**로 결론이 났다.

### 2-1. 판단 근거

참고군이 하던 일이 전부 다른 곳으로 갔다:

| 하던 일 | 간 곳 |
|---|---|
| 묶음 판정("N개 중 M개") | 집단군 판정 카드 (A2'가 또래 유병률까지 병합) |
| 또래 분포 | ③층 「같은 또래 분포」 카드 (A1') |
| 패널별 상태 요약 | ②층 계산기 카드들 |
| 항목별 수치·판정 | 검사항목 탭 |

**손실은 감수하기로 결정했다** — 상세 분석이 없는 연도에서 묶음 시각이 사라지고,
`CompareRow` 안에만 있던 약·고령 배지(`onMedication`·`isElderlyWarning`)가 함께 내려갔다.
§1-1②에 따라 무엇을 왜 뺐는지 코드 주석과 커밋 메시지에 남겼다.

### 2-2. 지키면서 지운 것

- **`computeGroupsForReport` 계산은 유지.** ③층 「같은 또래 분포」가 대표 묶음 선정과
  묶음별 분포 표시에 그대로 쓴다. 코드에 "삭제 금지"를 명시했다.
- **묶음 근거(`basis`, A7)를 이관했다.** 참고군 카드가 basis의 **유일한 렌더처**였다.
  그대로 지웠으면 전날 A7으로 충족한 §1-1③(분류·묶음도 근거를 밝힌다)이 하루 만에
  깨졌을 것이다. ③층 2뎁스의 묶음별 행 아래로 옮겼다.
- 참고군에서만 쓰이던 것 정리: `CompareRow`·`ATTENTION`·`metricsByKeys`·`topGroup`·
  `yearMetrics` + 미사용이 된 import 5개. **−178줄 / +23줄.**

## 3. 데모 8개 회차 전부 실분석 (`dbc8108`)

사용자 지적: *"24년 말고는 뭐 분석이 안되는데? 자동으로 다 되야 되는거 아니냐?"*

### 3-1. 진단 — 버그가 아니라 의도된 설정, 다만 문구가 거짓말

- **실계정은 원래 다 된다.** 업로드 때 `/analyze`가 그 해 수치로 계산해 그 해 record에
  저장하고, 프론트가 `recommendationsByYear`/`comboAnalysisByYear`로 꺼내 쓴다.
- **데모만 2024년에 붙어 있었다.** 더미가 한 벌뿐인데 전 연도에 복사하면
  "연도를 바꿔도 아래가 안 바뀌는"(= `2f39f72`가 고친 바로 그) 상태가 재현되기 때문.
- **그런데 화면 문구가 틀렸다.** "예전 방식으로 저장돼 있어"는 실계정 구버전 record용인데
  데모에도 그대로 나왔다. **데모엔 '저장'이라는 개념 자체가 없다.**
  발표에서 보면 "데이터가 구버전이라 절반이 비었구나"로 오해된다.

### 3-2. 처리 — 복사가 아니라 회차별 실산출

8개 회차를 각각 백엔드에 넣어 나온 결과를 연도별로 담았다. **한 벌을 복사하지 않았으므로
연도를 바꾸면 아래가 실제로 따라 바뀐다** — `2f39f72`의 개선을 이제 데모로 시연할 수 있다.

- `run_full_pipeline()` + `_inject_group_extras()` → combo_analysis · recommendations
- `analyze_renal()` → 그 해 크레아티닌·그 해 나이로 eGFR
- `run_timeseries_pipeline()` → change_pace (8회차·14년으로 재산출)
- 재현 스크립트를 **[tools/gen_demo_analysis.py](../../tools/gen_demo_analysis.py)로 남겼다** — 지어내지 않았음을 다시 확인할 수 있다

`highlights`·`insight`는 원래부터 수작업분이라(백엔드 산출은 항목명이 원문이고 21건)
2010년 첫 회차·14년 기준으로 손으로 고쳤다.

### 3-3. 2010·2012 추가와 페르소나 나이 변경

회차를 6개 → 8개로 늘리며 2010·2012를 추가했다. 검진 수치는 기존 궤적
(2014→2016 기울기)을 뒤로 이은 합성값이고, **그 위의 판정은 전부 계산 결과다.**

**나이를 1974 → 1968년생으로 바꿨다.** 지질 4종(총콜·LDL·HDL·중성지방)이 백엔드에서
만 40세 이상 항목으로 못박혀 있어(`peer_compare.SCREENING_AGE_MIN`), 1974년생이면
2010년(36세)·2012년(38세)만 지질이 빠져 또래비교가 "해당 연령 검진 항목 아님"으로
떨어진다. 1968년생이면 첫 회차가 42세라 8회차 전부 같은 항목 구성이 된다.

## 4. 페르소나 스펙 확정 (`1040466`)

### 4-1. 발견한 불일치

스펙을 정리하다 **분석과 프로필이 어긋나 있는 것**을 찾았다.

- 분석은 **음주자**로 판정하고 2022년부터 지방간 유형이 **MetALD(대사이상 + 유의한 음주 동반)**
- 그런데 `initialProfile`에 `smoking`·`drinking`·`alcohol_weekly_g`가 **셋 다 비어 있었다**
- 결과: ④층 「다음 검진 목표」가 `alcoholWeeklyG = 0`을 받아 **절주·금연 행동을 아예 못 냈다**

**한 화면이 지목한 문제를 바로 아래 층이 다루지 못하는 상태**였다. 원래 더미부터 있던
불일치이고, 연도별 재생성 때 기존 의미를 지키려다 그대로 남아 있었다.

## 5. 분석 탭 자기소개 (`2b3417e`)

사용자: *"분석탭에서 분석탭에서 하는 일을 말해주면 좋겠음"*

헤더 설명문이 `"내 수치, 정상 기준, 연령대 평균을 비교합니다"`였는데 **4층 재구성 이전

- **한 줄 교체** — "기준을 벗어났는지 보고, 검진지에 없는 값을 만들고, 또래와 견준 뒤,
  할 일로 옮깁니다." 네 층 이름을 그대로 써서 **목차 역할을 겸한다**
- **접이식 신설**(`TabIntroNote`) — 결론 문장 아래. 결론이 계속 맨 위에 오게 하고,
  자세한 소개는 원하는 사람만 펼친다. 문법은 `ScoreCalcNote`("어떻게 계산했나요?")와
  같게 두어 새로 배울 몸짓이 없다
- **`LAYERS` 상수 도입** — 층 이름을 한 곳에만 둔다. 전날 A4로 ③층 이름을 바꿨는데,
  그때 인트로가 있었다면 한쪽만 바뀌어 조용히 어긋났을 것이다

**연도 칩도 최신순으로 바꿨다**(`1040466`). 검사항목 탭은 원래부터 최신순이었고
분석 탭만 오름차순이라, 기본 선택인 최신 회차를 보려면 끝까지 스크롤해야 했다.
표시만 뒤집고 인덱스는 원래 것을 넘긴다. **히스토리 차트 x축은 시간순 유지** —
거기서 뒤집으면 추이가 거꾸로 읽힌다.

**패턴이 앞 문서와 같다.** 앞 문서 §5의 교훈이 *"뒤집힌 것은 전부 코드를 덜 보고 낸
처방이었고, 안 뒤집힌 것은 전부 코드로 확인한 관찰"* 이었는데, 이번에도 정확히 그랬다.
1·2·3 모두 **추측으로 낸 처방**이었고, parquet과 소스를 열어 보자 전부 뒤집혔다.

→ **결론: `calculator_percentiles_16yr.parquet`은 "미도달 자산"이 아니라 "안 쓰기로 한
자산"이다.** 32번 §4-1 목록에 넣지 말 것. 다음에 이 파일을 보고 같은 조사를 반복하지
않도록 여기 남긴다.

## 7. 도구가 준 교훈

### 7-1. Metro stale 번들 — 하루에 세 번 속았다

큰 구조 변경(B1·A3) 뒤 화면이 **바뀌기 전 상태**를 보여줬다. 세 번 다 코드·HEAD·Metro가
전부 정상이었고, 원인은 각각 달랐다:

1. 7/26부터 떠 있던 Metro의 stale 번들 (구·신 코드 혼합 → `NaN~NaN` 유령 버그)
2. Metro가 응답을 멈춤 (`UpdateFailedToLoad` 타임아웃)
3. 에뮬레이터 절전 후 reverse 터널이 끊겨 Expo Go가 캐시 번들로 되돌아감

→ **화면을 볼 때는 `adb reverse --list`부터 확인하고, 큰 변경 뒤에는 Fast Refresh를
믿지 말고 앱을 완전히 재시작한다.**

### 7-2. Metro는 워크트리 간 node_modules 공유가 안 된다

비교용 워크트리에 node_modules를 정션으로 공유시켰더니 Metro가 **심볼릭 링크의 실제
경로 기준으로 모듈을 해석**해 `Unable to resolve module ../../App` 500 에러가 났다.
→ 워크트리마다 따로 `npm install` (14초면 끝난다).
